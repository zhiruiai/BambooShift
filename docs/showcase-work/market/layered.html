SQLite + PostgreSQL

分层架构建议

终端断网独立采集用 SQLite 嵌入进程内零配置读写；总部并发汇总用 PostgreSQL 服务端处理多用户事务。两库不自动同步，需另行实现可重试同步、去重与冲突处理。边界：同步逻辑由应用层负责，此台仅给出分层方向。

现场 SQLite⇌同步通道⇌中心 PostgreSQL同步需另行实现：可重试、去重、冲突处理

产品能力证据

全部SQLitePostgreSQL
SQLite

SQLite 直接在应用进程内读写本地文件，部署时无需单独的数据库服务器进程。

Serverless ↗
SQLite

每个数据库文件同一时刻只有一个写入者。大量客户端同时通过网络直接读写同一数据库时，官方建议考虑客户端／服务端引擎。

When to use ↗
PostgreSQL

应用通过客户端连接数据库服务进程。服务器可以处理多个并发客户端连接。

Architecture ↗
PostgreSQL

MVCC 支持事务快照。在查询与普通写入之间，读写互不阻塞；相互冲突的写入仍可能等待。
