# 远程代码执行

本文说明当前源码中的 `remote_shell` 能力、部署条件和维护边界，不构成产品 GUI 或某个 Linux 部署已通过验收的证明。它通过已连接的远程 Computer Worker 执行一次经批准的命令，不是完整 Linux 桌面、交互式终端或常驻后台服务。

## 使用与审批

Bot 通过现有 `computer_action` 工具提出 `remote_shell` 请求。仅连接到声明 `isolated-shell-v1` 且通过隔离探测的远程 Worker 时才接受请求；本机 `LocalComputer` 明确拒绝执行此类型，不会回退到宿主机 shell。

请求包含 `command` 与 `path`。命令非空，最多 16,000 个字符，不能包含空字符。`path` 是相对于远程工作区根目录的工作目录，默认 `.`；最多 4,096 个字符，不接受绝对路径、反斜杠、空字符或 `..` 路径段。调用者不能指定宿主目录、身份、挂载、网络开关或延长执行时间。

请求首先进入待审批状态。聊天操作卡及电脑面板展示完整命令、相对工作目录、执行限制与文件影响范围；用户选择“允许本次操作”或“拒绝”。批准只适用于这一次操作，不批准其他待处理请求。权限沿用现有电脑审批，未新增团队角色或权限体系，也没有添加直接启动终端的按钮。

命令可读取、创建、修改或删除当前工作区中的文件。所有 Bot 共用该工作区，因此修改可能影响其他任务。**已经发生的写入不会因失败、取消、超时或断开连接而回滚。** 文件交付仍使用已有取回文件与聊天资料库流程，命令产生的路径不会自动成为聊天下载链接。

原有 `terminal_command` 继续只接受 `pwd`、`ls`、`date`、`uname` 四项只读命令，属于既有只读操作；它与需要逐次批准的 `remote_shell` 是不同的动作类型。新增远程能力没有放宽本机命令范围。

## 执行与结果

命令通过隔离环境中的 Bash 执行，固定最长 30 秒。取消和超时后仍需等待监督器清理子进程；30 秒不是 HTTP 响应或清理流程必定完成的时限。一个 Worker 的执行队列串行处理操作，命令不能作为脱离本次任务的后台进程继续运行。

标准输出与错误输出合计最多保留 256 KiB，按 UTF-8 字节计算；超过上限后标记 `truncated`。结果包括 `stdout`、`stderr`、`exitCode`、`timedOut`、`cancelled`、`durationMs`，以及可选的 `signal` 和 `resourceLimit`。退出码可能为空，非零退出码表示命令失败；收到操作响应本身不代表命令成功。

界面将命令与输出作为纯文本展示，不执行其中的 HTML。结果默认折叠，长输出在卡片内滚动；退出码、终止信号、超时、取消和资源限制原因分别显示。协议支持的资源原因是 `memory`、`disk-reserve`、`pids`；实际原因以监督器返回值为准，不从任意错误文本猜测。资源耗尽与隔离环境异常分别处理，合法资源限制结果本身不会永久停用能力。

进程限制原因来自本次任务 cgroup 的 `pids.events`。程序可能捕获创建进程失败后自行处理并以退出码 `0` 结束，此时仍保留“进程数已达上限”的事实，需要同时查看退出码与输出，不能把资源标记直接解释为隔离故障。

## 隔离与资源边界

Linux 监督器为每次执行建立独立挂载、PID 和网络命名空间，构造只读运行环境，并使用 cgroup v2 约束任务。命令以固定 UID/GID `65532` 运行，清除附加组和 Linux capabilities，设置 `no_new_privs`。Node 启动监督器时使用限定环境变量，任务再使用单独的干净环境，不继承模型密钥、Worker token 或宿主用户的 shell 配置。

工作区在任务内挂载为 `/workspace`，是持久可写区域；`/tmp` 是本次执行的临时内存文件系统。程序和运行库以只读方式挂载，运行环境不开放宿主的完整文件系统或控制目录。网络命名空间不提供外部联网能力，不能依靠这项功能在线安装依赖或访问工作区外的服务。需要的工具和库由维护者预先部署。

| 资源         | 当前实现                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 执行时间     | 30 秒固定上限；监督器清理等待另计                                                                         |
| 保留输出     | stdout 与 stderr 合计 256 KiB                                                                             |
| 任务内存     | cgroup 上限 512 MiB，禁止交换空间，启用整组 OOM 处理                                                      |
| 进程数量     | cgroup `pids.max = 64`，限制包含同组任务进程                                                              |
| CPU          | cgroup 配额等效一个 CPU 的时间份额；任务进程另设 CPU 时间限制                                             |
| 临时目录     | `/tmp` 大小 64 MiB，本次执行结束后销毁                                                                    |
| 单文件写入   | 任务进程 `RLIMIT_FSIZE` 为 64 MiB                                                                         |
| 持久存储余量 | 启动前及执行期间检查工作区所在文件系统至少保留 96 MiB 可用空间和 1,024 个可用 inode；运行中不足则停止任务 |
| 写入速率     | 对提供 `io.max` 且具有适用块设备编号的环境，设置每秒 8 MiB 写入上限                                       |

这些限制不构成工作区总容量配额。单文件限制不限制多个文件的累计大小，临时目录上限也不限制持久工作区。存储余量检查是周期性监测，不能保证检查间隔内绝不耗尽磁盘；写入速率限制还取决于实际文件系统和 cgroup 支持。生产部署仍应为远程工作环境分配独立容量并管理留存文件，不能把宿主数据盘总大小当作每个任务的配额。

## 取消、重放与故障

任务取消、人工接管、切换界面、换连接、HTTP 中断或 Worker 关闭会触发停止流程。Node 向监督器发送终止请求，由监督器清理 cgroup 和后代进程，并等待确认；不会将客户端请求被取消等同于远程命令已经停止。

控制端使用独立于原取消信号的请求确认停止状态。Worker 只有在命令尚未启动或已收到有效最终结果时才确认已停止。若监督器异常退出、结果协议无效或清理状态无法确认，Worker 拒绝后续执行且健康检查失败，控制端停用连接。重新点击连接不会清除这个状态，需要维护者确认并处理原因。

请求绑定 Worker 实例与控制台来源，入队和执行时再次校验。操作 ID 在同一 Worker 实例生命周期内保留，取消先于执行到达时也会留下拒绝执行记录；旧请求不会因结果缓存淘汰而重新运行。记录达到容量上限后拒绝新命令，须经维护后显式重启 Worker。重启产生新的实例 ID，旧实例请求仍不能复用。

普通命令的非零退出、经确认的取消、超时和资源限制结果可以保留已产生的输出。它们不会撤销文件修改，也不会自动重新执行命令。

## 启用条件

部署前按 [Python 控制程序构建](python-control-build.md) 从完整源码构建并核验 `.build/python-tools/isolated-shell.py`。不要将开发入口 `scripts/isolated-shell.py` 单独复制到远端；源码入口会调用本机构建器，部署产物则不再加载仓库模块。

这项能力需要在专用远程 Linux 运行环境中部署。仅设置环境变量并不代表启用成功；未配置、探测失败、验证记录不匹配或存在未恢复任务时，不应声明能力。

Worker 读取以下两个环境变量，值均须是绝对路径：

| 变量                                | 用途                                        |
| ----------------------------------- | ------------------------------------------- |
| `OPENBOT_ISOLATED_SHELL_PYTHON`     | 启动监督器的 Python 解释器                  |
| `OPENBOT_ISOLATED_SHELL_SUPERVISOR` | 部署后的单文件 `isolated-shell.py` 构建产物 |

两项均配置时，Worker 才创建可探测的执行器。已有 `OPENBOT_WORKER_WORKSPACE` 也须与监督器声明的工作区完全一致，当前固定为 `/opt/openbot/workspace`。Node 会核对探测结果的工作区，不接受任意目录映射。

监督器要求以 root 执行，当前 Worker 通过子进程直接启动它；没有自动提权、sudo 代理或另一个特权 HTTP 服务。任务中的实际命令随后降权为 `65532:65532`。部署必须具备 Linux 命名空间、挂载和 cgroup v2 所需权限；不能仅依据“容器”或“PVM”名称推断这些能力已经可用。

运行环境须提供 `unshare`、`setpriv`、Bash、Python 及其运行库，当前只读运行环境还使用 `/usr/bin`、`/usr/lib`、`/usr/lib64`、解释器对应的标准库/共享库和 `/opt/node`。这些路径与监督器检查必须匹配。安装缺失软件、创建控制目录和配置 cgroup 属于部署步骤，应用不会自动执行。

监督器固定读取 `/opt/openbot/shell/config.json`，字段如下：

| 字段          | 当前允许值                                                                       |
| ------------- | -------------------------------------------------------------------------------- |
| `version`     | `1`                                                                              |
| `workspace`   | `/opt/openbot/workspace`                                                         |
| `uid` / `gid` | `65532` / `65532`                                                                |
| `cgroupRoot`  | `/sys/fs/cgroup/openbot-shell-` 加 32 位小写十六进制标识，且为已经配置的专用目录 |

配置文件必须由 root 拥有、权限为 `0600`，并为无额外硬链接的普通文件。控制目录及其父目录、监督器和相关运行库须满足源码中的所有权与不可被组/其他用户写入的检查；cgroup 目录须已启用 CPU、内存与进程控制器，并支持任务清理所需接口。缺少条件时应保持功能不可用，不降低隔离要求继续运行。

## 验证与维护

维护者完成部署后，使用所配置的解释器和监督器显式执行：

```sh
"$OPENBOT_ISOLATED_SHELL_PYTHON" "$OPENBOT_ISOLATED_SHELL_SUPERVISOR" --verify
```

`--verify` 会运行真实隔离检查命令，成功后写入 `/opt/openbot/shell/verified.json`，绑定当前监督器文件和配置的摘要。它不是只读检查：执行准备可能将符合条件的工作区文件归属调整为任务 UID/GID，并记录原所有权和权限至私有维护日志。不能将验证理解为不接触现有工作区。

修改监督器或配置后必须重新验证。Worker 的能力探测存在进程内缓存，已被停用的执行器不会自行恢复；维护完成后应显式重启 Worker，再在产品中重新连接。探测入口 `--probe` 只检查当前条件和验证记录，不安装组件、不执行恢复。

若有遗留任务，先停止调度新任务并确认维护范围，再显式执行：

```sh
"$OPENBOT_ISOLATED_SHELL_PYTHON" "$OPENBOT_ISOLATED_SHELL_SUPERVISOR" --recover
```

`--recover` 获取执行锁，清理这个监督器专用 cgroup 下的任务进程及遗留任务目录，随后重新运行验证并更新验证记录。它不会回滚工作区内容，也不应作为普通失败命令的自动重试手段。若无法确认所有进程已清理，继续保持停用，不能仅删验证文件或任务记录以绕过检查。当前没有应用内自动安装、自动恢复或一键重置执行环境的接口。
