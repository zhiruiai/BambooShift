# 共享 Bot、私人会话与任务发起者

2026-11-05 对照 [Grok Bot 共享说明](https://docs.x.ai/grok-bot/shared-bots)与[协作说明](https://docs.x.ai/grok-bot/chat-and-collaboration)核对。共享 Bot 使用持续更新的同一个定义，每个人的会话应彼此隔离；[模板](bot-templates.md)则是导入后独立维护的副本。这两个能力不能互相替代。

## 已实现的实时共享

来源空间拥有者可以把自己维护的 Bot 共享给所属团队的全部成员或选定成员。来源可以是个人空间，也可以是团队空间；团队来源只能共享给原团队。接收者明确选择自己的有效个人空间后加入，得到稳定的本地 Bot 引用与私人单聊。分享链接和目录始终检查当前产品账户及团队资格，不是匿名公开模板，平台运营登录也不能代替接收者身份。

共享的内容是来源名称、角色、简介、长期指令、原创头像形状、颜色及当前启用的技能；图片头像通过带版本和身份检查的来源接口显示。个人引用不复制来源技能表、例行任务、聊天、记忆、附件、模型密钥、应用凭据或电脑登录。来源配置与技能更新后，目录和 Bot 设置显示最新内容；读取不会把定义同步写入接收者数据库；目录与加入回执读取也不会启动尚未初始化的个人运行环境。

每个个人空间对同一共享记录只有一个 Bot 引用和主私人会话。加入请求持久保存回执，同一请求重试不会重复创建，另一次明确加入也复用原会话；隐藏后再次加入会恢复原入口并保留历史。关闭页面或刷新不自动加入、开工或重新提交未知结果。原私人会话不能通过普通删除、改名或改成员接口拆改；不再使用时可隐藏该 Bot。

接收者可以与引用交谈、保存自己的记忆、使用个人资料库，也可以把它加入自己的工作组或设置个人例行任务。来源配置和技能只读，不允许修改、批准新技能分叉、复制、制作模板、再次分享或选为个人主 Bot。来源拥有者和团队其他成员不能读取接收者的私人会话、记忆、文件、电脑状态或加入回执。团队原有会话仍然团队可见；“选定成员共享”控制谁能加入个人空间，不会改变原团队空间的访问范围，也不拆分过去的团队历史。

共享管理、目录、分享链接、加入个人会话和只读 Bot 面板沿用现有界面组件。新增页面与交互尚未完成真实桌面和手机 GUI 验收。

## 明确授权的来源资料

来源拥有者可以在共享设置中选择已登记资料，确认精确文件版本后保存。候选可按名称搜索，每次最多显示 200 个匹配项；已选资料不因搜索或分页上限丢失。最多授权 32 份、合计 50 MiB，单份最多 10 MiB。仅勾选或下载预览不会发布，最终“保存并共享”才提交授权；上传到资料库也不会自动共享。

每项授权绑定文件 ID、原登记名称、类型、创建时间与实际字节摘要。来源内容或登记信息变化后，旧授权不可读取，需要拥有者重新确认并保存新版；删除后显示不可用，同名新文件不会继承旧授权。成员只看已批准的名称、大小、类型和版本，不会通过过期状态看到未批准的新名称或来源目录路径。拥有者确认新授权版本后，个人面板随共享更新刷新；未确认的原文件字节变化不自动发布，可手动刷新查看状态，下载始终以服务器当前授权为准。

共享 Bot 通过 `shared_file_list` 与 `shared_file_read` 读取本轮固定清单，支持现有 UTF-8、PDF、DOCX 和图片解析；图片仍要求模型支持视觉。读取只接受清单内文件 ID，不接受来源路径、URL 或其他空间标识。来源文件不会自动写入个人资料库、工作区或电脑，不能把它的 ID 直接作为个人电脑上传 ID。未授权文件、原会话、其他记忆和密钥仍不可见。

文件授权新增、删除或换版本会使旧运行授权失效。成功读取过的文件还会在后续权限检查中核对登记记录和文件状态；原文件被修改或删除时中止相关运行。尚未使用的文件不可用，不会单独阻止整个 Bot 启动。解析前后重新核对权限，取消会等待解析进程退出。

成员可以明确下载仍获授权的版本；请求绑定当前账号，换号或失去资格后不能继续取得新内容。移除文件授权或撤销共享限制后续访问，无法撤回已经下载到用户设备的副本，也不能抹去已经进入个人聊天或模型上下文的内容。文件授权本身不授予来源应用、来源电脑或团队知识库权限；来源应用需要下述单独选择。

Web 下载绑定当前授权版本；版本改变时取消旧请求并释放临时对象，迟到内容不会触发保存。桌面客户端使用原生保存窗口，保留同样的固定账号和版本检查，保存前再次核验授权；页面跳转、账户变化或关闭窗口会取消未完成下载。若保存目录在下载途中被其他程序改名，失败时通过原文件句柄清除未发布正文，可能留下空临时文件；正常已保存的文件不因后续清理失败被清空，但删除失败可能留下成品的临时硬链接。原生保存窗口与覆盖确认尚未进行产品 GUI 验收。

## 明确授权的来源应用

来源拥有者先在“连接应用”中配置真实连接，再到 Bot 的共享设置中展开“提供给成员的应用”，查看工具说明和参数，逐项选择后“保存并共享”。仅展开目录或勾选草稿不会授权。最多选择 20 个应用、每个应用最多 64 项工具；已选工具的完整说明和参数合计不超过 512 KiB。新发现的工具不会自动加入授权，未选择的工具不能调用。

成员在个人空间“连接应用”的“发布者提供的应用”中只读查看可用工具，在聊天中请求共享 Bot 使用。应用账户由发布者提供；每次操作，包括只读工具，仍由本次任务的发起者确认应用、工具及参数后批准一次。审批卡标明来源，发布者不能代替成员批准，也不能借此读取个人会话。工具参数会发送给对应外部服务，应在确认时核对。当前空间自己的应用连接继续独立管理，不能因连接 ID 相同而混用两边账户。

授权固定来源连接版本及每项工具名称、说明和参数定义的摘要。重新连接、换凭据、重新进行网页登录授权或工具定义变化后，旧版本不可继续使用；来源拥有者查看最新内容、明确更新选择并保存后才能使用新版。移除授权或撤销分享会取消相关待审批操作并中止在途任务；已经使用过的来源应用仍受整个根任务的权限检查，子任务结束不移除检查。普通 OAuth 令牌刷新在授权主体和范围保持一致时沿用原连接版本，不要求每次重新共享；刷新失败或范围变化则停止调用并要求来源拥有者处理。

凭据保存在来源空间，实际调用复用来源服务端已有连接，不复制到成员数据库、模型或客户端。成员目录只返回已批准的应用名称、工具及版本，不返回服务地址、凭据或未选工具正文。元数据读取不联网、不初始化来源运行环境；来源执行服务不可用时明确拒绝，不回退到成员的同名连接。调用与取消沿用[应用连接](app-connections.md)的规则：外部操作发出后结果可能未知，停止不表示回滚，也不会自动重试。尚不提供“始终允许”、无需逐次审批或自动扩大工具授权。

## 任务发起者与运行权限

普通聊天任务在接收消息时固定真实登录账号、原登录会话和空间成员关系。请求正文、模型参数、保存的显示姓名不能指定审批人。根任务在消息投递完成后仍保留后端授权，子任务继承它；每次模型初始化、工具执行前后、结果发布和异步电脑准备后重新验证。平台权限变动立即取消相关执行；运行期间也检查自然到期的登录。

同一个发起者可以继续补充要求；其他成员的消息留在队列，前一个任务结束后作为独立任务执行。停止自己的任务只取消该发起者尚未执行的补充，不会把下一位成员的排队消息一起删除。根任务首次使用一个 Bot 时固定配置和有效技能快照，同一根任务重复委派它也沿用该快照；来源编辑从下一次根任务生效。

运行同时保留发起者授权与所有参与 Bot 的来源授权。共享范围、目标团队或共享状态变化会使旧授权失效；即使某个共享子任务已经结束，也不能在父任务中继续使用已撤销来源的结果。取消会传到模型、工具、待审批操作与实际电脑清理。仍有资格的用户可以在下一次明确任务中取得新授权；不会为了继续旧任务自动重放。

应用操作和需要批准的电脑操作显示发起者。只有本人能批准或拒绝，拥有者不能替另一位成员作决定；同账号的另一有效登录可处理审批，但发起任务的原登录失效后，任务本身也失效。无浏览器来源的定时任务由空间拥有者身份授权，不借用最后打开页面的成员；拥有者或空间不可用时停止。历史未绑定账号的操作仅允许空间拥有者处理，本地旧版继续兼容。

停止、退出、成员移除和权限变动沿任务传到应用与电脑执行。已经发送给外部服务的操作可能产生效果，失败或取消时保留结果未知，不自动重试，也不把中止请求描述成回滚。电脑清理等待实际完成后才释放后续使用；请求者信息可以持久化用于显示，授权函数只在服务端内存中存在。

审批、停止和手动电脑请求同时固定前端账号及空间，拒绝换号后迟到的操作。应用连接、模型、电脑连接与维护仍由空间拥有者管理，普通成员能够处理自己的审批不等于获得这些配置权限。

## 私有数据与执行资源

当前团队空间的单 Bot 会话和群会话都属于团队空间，消息、记忆、文件仍团队可见。界面现在明确显示“团队可见”；个人空间显示“仅你可见”。没有根据历史消息作者猜测并拆分旧会话，也没有把隐藏侧栏或前端过滤描述成隐私隔离。

共享私人会话在接收者自己的空间保存独立的 Pi 会话、消息、记忆和资料库，使用该空间的模型配置、应用连接与电脑协调器。明确授权的来源应用通过独立能力在来源服务端调用，不把来源凭据复制成个人连接。后台授权组合最新共享资格与个人空间拥有者资格；例行任务也必须遵守来源工具清单与逐次审批，不继承来源登录或其他未授权资源。

这不意味着每个成员已经自动分配云电脑。当前唯一已授权远程实例及两个 Bot 画面仍归属原绑定空间；新注册空间不会继承其连接、登录或文件。未配置自己的执行电脑时，相应工具明确不可用，不会回退到来源电脑。

撤销分享、移除共享成员、停用相关账户或空间、删除来源 Bot 后，相关私人执行和审批停止，后续任务不能使用本地保存的旧定义继续工作。个人历史仍保留，引用显示不可用；共享权限失效不把这些历史交还来源拥有者。

## 实现与验收边界

中央 `shared_bots` 登记只保存来源、访问范围、版本、明确授权的文件元数据及应用工具名称与版本摘要，不保存文件正文、应用凭据或完整工具参数定义；接收者数据库独立保存 `shared_bot_refs` 与加入回执。来源配置由只读 SQLite 查询取得，个人 Store 通过只读投影显示它；运行状态更新仍写原始本地引用，避免把显示投影变成副本。Pi 禁用自动扫描来源技能文件，直接使用受控快照中的有效技能正文。

[Rust 共享文件读取器](../server/api/src/shared_bots/files.rs) 只打开平台登记空间内的现有文件，不创建来源目录或运行环境；拒绝软链接、硬链接、特殊文件、超限与读取中发生变化的文件。通过[工作区文件访问层](../server/api/src/workspace/file_storage.rs)持有并核对目录、文件身份；这是文件访问控制，不声明完整操作系统隔离。旧 Linux 电脑工作区证据不能替代当前共享文件路径的独立验收。

[Rust 来源应用读取器](../server/api/src/shared_bots/source_apps.rs) 从现有来源数据库只读取得应用目录并核验选定版本；模型使用独立的 `shared_app_list`、`shared_app_tools`、`shared_app_call`，个人 `app_*` 工具仍只访问个人连接。服务端为每项审批绑定原执行器，重启不将来源审批解析为个人连接，也不重放操作。

团队知识的细粒度授权尚未实现，个人偏好不会自动发布成团队知识；来源电脑与未授权资源仍不继承。公开模板、实时共享、文件版本授权和来源应用授权是不同能力，不能据此宣称完整 Grok Bot 已复刻完成。

当前真实 Pi 临时模型与平台 HTTP 合同见 [共享运行测试](../server/api/tests/shared_bots_runtime.rs)及[共享 HTTP 测试](../server/api/tests/shared_bots_http.rs)：覆盖来源定义实时更新、私人数据隔离、原会话恢复、来源拥有者与其他成员拒绝访问、撤权后的审批和下一次任务拒绝。先前发起者基础检查仍保留在[验证记录](evidence/requester-verification.json)与[服务检查](evidence/requester-service.json)。本轮没有调用付费模型、修改正式用户数据或新增远程实例；最终完整回归由[验收记录](verification.md)汇总。较早批次曾被浏览器控制限制阻挡；其接口与组件结果不代表页面视觉或触控验收。后续页面记录与当前完整回归分别见验收记录。

文件版本授权由[共享资源测试](../server/api/tests/shared_bots_resources.rs)与真实 Pi 合成端点覆盖精确版本、权限、原文件变化、读取竞态、异步解析撤权及个人资源分离。Web 下载、组件事件与原生客户端桥接各自验收，接口通过不代表系统保存对话框、手机操作或新页面视觉已验收。

来源应用合同见[共享应用测试](../server/api/tests/apps_shared.rs)、[Pi 共享应用测试](../server/api/tests/agent_apps_shared.rs)及应用审批回归：使用临时账户、真实平台 HTTP、生产 Pi 和自有 MCP 服务，检查目录隐私、本人审批、来源与个人同 ID 连接隔离、OAuth 正常刷新、版本变更及撤权后的晚结果。没有连接真实第三方账户；接口及 React 事件验证不代表共享应用页面的产品 GUI、手机触控或真实服务商操作已经验收。
