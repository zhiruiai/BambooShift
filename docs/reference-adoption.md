# Reference adoption and remaining gaps

Reviewed on 2026-11-13 (Asia/Shanghai). This is a feature and dependency inventory, not a claim of complete compatibility with another product. BambooShift keeps one authoritative Rust workspace service for identity, permissions, approvals, persistence and scheduling. Web, Electron and Flutter use that service; Pi and integration workers execute bounded protocols.

## Sources and permission to reuse

- **Grok Bot**, specifically the team product documented under [`docs.x.ai/grok-bot`](https://docs.x.ai/grok-bot/overview), is the product reference. Ordinary Grok chat, Grok Build and the xAI API are separate products. Public documentation is evidence of behavior, not a license to copy proprietary prompts, marketplace templates, illustrations or characters.
- **OpenMausBot** is an independent reference project, reviewed at [commit `4355688e07abd27187dd5f1559f67fedd62b0dd0`](https://github.com/milind-soni/OpenMausBot/tree/4355688e07abd27187dd5f1559f67fedd62b0dd0). Its [LICENSE](https://github.com/milind-soni/OpenMausBot/blob/4355688e07abd27187dd5f1559f67fedd62b0dd0/LICENSE) and [NOTICE](https://github.com/milind-soni/OpenMausBot/blob/4355688e07abd27187dd5f1559f67fedd62b0dd0/NOTICE) were read. This revision is Apache-2.0, not MIT. Any future source transplant must preserve the applicable notices and identify modifications.
- The additions described here were independently implemented or authored. No Grok Bot or OpenMausBot prompt, template body, artwork, avatar or UI source was transplanted. The six newly authored catalog entries follow the project's MIT license; this review does not establish the provenance of every historical or user-imported template. Dependency licenses remain their own.
- A shared template is not automatically licensed for redistribution. Review its explicit license and included assets before considering reuse. A public URL, install button or GitHub star count is insufficient.

## Catalog additions and reuse

The pre-change catalog contained seven single-Bot profiles, six team plans and seven skill workflows. Those existing entries were reviewed for overlap; their historical authorship was not independently re-audited. Existing research, writing, coordination, engineering, organization, briefing and support entries were kept. Existing launch, month-end close, support, study, creator and meeting teams were kept.

| New entry                     | Gap it fills                                                                                               | Concrete output                                                                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `analysis` Bot                | Dataset coverage and metric definitions are not the same role as coding or general research.               | Reproducible findings with denominators, exclusions and unresolved data issues.                                                                          |
| `data-quality-review` skill   | A repeatable pre-analysis check was absent.                                                                | Coverage, duplicate/missing-key checks, join inflation checks and reconciliation exceptions.                                                             |
| `account-health-review` skill | Proactive review of existing accounts differs from reactive support triage.                                | Dated evidence, explicit criteria, uncertainty and a prioritized follow-up draft.                                                                        |
| `account-health` team         | The catalog lacked a handoff from signals through context review to customer follow-up drafts.             | Three editable roles: signal analyst, context reviewer and follow-up editor.                                                                             |
| `recruitment` Bot             | AI staffing needs a role distinct from project execution or human recruiting.                              | Reviewable Bot/team proposals with existing-colleague reuse and accurate tool-visibility limits.                                                         |
| `software-product` team       | No existing team covered product design through backend, frontend, independent QA and delivery acceptance. | Six editable roles with sequential handoffs, bounded rework and explicit evidence requirements. See [workflow and acceptance](software-product-team.md). |

The six catalog additions above are bilingual original text. The account-health use case is informed by the linked official documentation; its prompt bodies and team assignments were written independently rather than copied or translated from an upstream template. They work with supplied material and already authorized tools. They do not assert that CRM, email, spreadsheets or a computer are connected. No new parser, workflow engine, transport or dependency was added for these catalog entries.

Thus this is a preference for mature MIT components where applicable, **not a claim that every existing or transitive dependency is MIT**. New component selection must inspect the exact shipped package and its notices. Do not remove working dependencies or layer duplicates solely to change a license label. [Third-party notices](../THIRD_PARTY.md) and `legal/third-party/` remain the release sources of record.

Cordis 3.18.1 does not await every asynchronous disposal callback itself. The host registers and awaits cleanup explicitly, unregisters tools first, cancels pending calls and rejects late results. Plugin diagnostics do not write arbitrary details to the framed worker stdout. Lifecycle tests cover successful and failed cleanup. This is reliability handling inside a trusted worker, not a security boundary.

## Verification and follow-up

The targeted Web/worker run passed **27 tests**, including starter catalog behavior, complete export, local identity, both shell result surfaces and Cordis lifecycle. The targeted Flutter run passed **25 tests**, including bilingual catalog assets, narrow-screen library/team previews, skill draft submission, export cancellation, local identity and local-shell presentation. Catalog tests compare the shared and Flutter Bot assets byte for byte. The existing Rust team-starter integration test now exercises the new team in both languages without creating Bots or jobs merely by loading a draft; the backend integration run passed.

Remaining work is explicit in the inventory: whole-workspace migration, broad portable team packages, local setup discovery, GitHub skill resource bundles, mobile batch MCP import and unreviewed upstream modules are not delivered by this change. Native desktop permission/capture acceptance, avatar animation states and asset licensing have independent validation requirements.
