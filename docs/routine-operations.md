# 例行任务的创建与手动运行

聊天详情和空间管理页共用例行任务面板。新建任务和「立即运行」会保存一份操作回执；网络中断后先「检查原请求」，不会自动重新创建或运行。拿到回执后可打开所属会话核对，已有编辑草稿仍受离开确认保护。

## 明确重试与恢复

每次明确操作生成一个请求标识，和当前账户、工作空间及提交内容绑定。相同标识与内容只返回原回执；修改任务标题、内容或时区后不能沿用同一个标识提交不同请求。创建成功后即使原任务已被删除，重试也不会把它恢复。

运行请求还包含点击时看到的任务配置。若原请求尚未被接纳，而另一窗口已经修改了配置，服务端会要求重新核对，避免重试旧点击却执行新内容。下次执行时间和上次执行时间不属于配置比较范围。原请求一旦接纳，之后编辑或删除例行计划不会改写已经开始的这次执行；停止仍通过会话中的任务控制处理。

当前页面保留原提交内容，用于明确重试同一份请求。浏览器会话存储只保存标识、类型和内容摘要，不保存任务正文。恢复标识无法保存时保留输入且不发送请求，避免提交后无法核对。关闭面板或刷新后可以查询原回执；没有原正文时不根据当前草稿拼出另一次提交。未查到回执也不等于原请求从未到达，在原页面重试仍使用完全相同的标识和内容。服务端明确证明未接纳的拒绝才允许解除原操作的等待状态。

刷新后原提交内容已不在当前页面时，可选择「结束提交核对」。服务端在同一事务中判断：已接纳的操作只返回原回执，不停止正在运行的任务；尚未接纳的操作则持久关闭原请求标识。原请求之后即使迟到，也不能再创建或启动任务。关闭响应再次丢失时，仍可继续查询同一标识，查到原回执则显示原结果，确认请求已关闭则解除等待；当前页面的草稿保留。

## 一次接纳与实际结果

创建任务与创建回执在同一 SQLite 事务中提交。手动运行把人工发起消息、会话时间、例行任务的上次与下次时间、操作回执一起保存；提交成功后才进入 Pi。数据库写入失败会整体回滚，尚未保存的请求不会调用模型。

「立即运行」属于实际点击者的任务，使用该账户和登录会话的授权，目标 Bot 固定为所选任务的负责人。正文里的另一个 Bot 名称不会改换负责人。登录撤销后，运行与后续工具操作停止沿用旧权限；已经发往外部服务的操作不能保证撤回。

「已提交」只表示请求已被接纳。Pi 可能经过多个回复和工具调用，中间回复结束不等于整轮完成。最终回执由实际运行的收尾结果写入，并关联原输入与最终回复，分别显示完成、失败、取消或中断。模型返回错误即使被运行器转换为聊天文字，也不会被记录成成功。回执最终写入出现故障时保守显示中断，不会再次派发任务。

服务重启把未确认结束的手动请求记为中断，不自动重放。即使先前操作已在外部产生效果但本地结果没有保存，也必须先核对聊天与外部状态；同一请求重试仍返回原记录。该保障是持久的一次接纳，不是外部操作在所有故障下恰好执行一次的承诺。

## 参考与边界

Grok Bot 的说明区分例行任务创建后的下一次定时执行与手动 Test，并要求在聊天中核对执行结果；还描述自然语言创建/修改、事件触发、手机运行历史及额度等功能。见[官方例行任务说明](https://docs.x.ai/grok-bot/skills-routines-and-automations)。本轮补齐本项目的手动提交和恢复链路，不把回执当作完整运行历史或上述其他能力已实现的证据。

现有按时调度策略保持不变，详见[时区与计划](time-zones.md)。旧版兼容接口 `/routines` 与 `/routines/:id/run` 仍保留原行为；新版聊天和空间管理入口统一使用 `/routine-operations`，不会在新接口失败时自动回退。普通编辑、暂停和删除没有在本轮扩展为通用操作回执系统。

验证使用临时账户、数据库、本机 HTTP 模型替身与真实 Pi。覆盖原子提交、实际权限撤销、多轮工具调用、模型失败、断线、重启与原消息导航；这些测试不代替真实产品页面的视觉、焦点、触控和原生客户端验收，也未调用付费模型或操作指定远程电脑。
