# Bot 复制与模板

参考 [Grok Bot 的 Bot 管理说明](https://docs.x.ai/grok-bot/bots)，Bot 详情提供复制与分享入口。复制前查看完整配置，分享先生成可编辑草稿，再明确发布。模板也可以从“连接应用”中的模板入口查看。账号注册、登录后返回原模板，添加到自己拥有的空间。

桌面、Web 和 Flutter 共用七个原创 Bot 模板，包括研究员、写作编辑、项目协调员、编程助手、日程整理员、晨间简报员和工单分流员。可以在「Bot 模板库」和「新建 Bot」搜索、按类别筛选并查看长期指令。工作空间拥有者可继续编辑并确认创建，其他成员可以查看模板。多人场景可由当前空间拥有者从「模板库 → 团队模板」查看分工并载入方案。 [团队模板](bot-settings-and-teams.md#从团队模板开始) · [Grok Bot 场景示例](https://docs.x.ai/grok-bot/use-cases)

## 配置范围

预览包含名字、角色、简介、长期指令、头像、颜色、已启用技能以及例行任务的目标、计划与开关。技能草稿、停用版本和历史版本不随副本携带。头像以已规范化的图片迁移，目标空间得到自己的资源标识。

从团队技能目录导入的版本保留在目标 Bot 的本地技能中。Bot 模板、复制与实时共享只投影可以随 Bot 转移的技能。

复制不携带聊天、学到的记忆、文件、应用凭据、电脑连接、主 Bot 身份或个人名单偏好。原 Bot 和副本随后独立演进；更新或撤销原模板不会修改已导入的副本。模板正文中主动填写的文字会进入预览，发布前应直接检查、编辑需要分享的内容。

同空间复制默认保留例行任务开关，外部模板导入默认暂停，均可在确认前选择。来源已关闭的任务不会因“保留开关”而开启；启用任务从创建之后的下一次计划执行，不补跑来源的旧计划。技能在确认后作为新 Bot 的第一个启用版本保存，并同步为 Pi 可读取的技能文件。

## 草稿与发布

分享草稿与来源 Bot 独立。编辑草稿不会改变来源 Bot 或公开版本；“从 Bot 更新”需要重新预览来源，再明确替换草稿。草稿可编辑资料、长期指令、技能和例行任务，可移除头像；换成另一张上传图片先修改来源 Bot，再更新草稿。

发布校验页面刚查看的草稿版本。相同分享范围内更新会保留链接，打开链接的人看到新发布版本；已经预览旧版本的接收者必须重新查看后才能导入。撤销或改变分享范围会永久停用旧链接；再次发布生成新链接。

公开模板会出现在模板列表，任何能访问这个 MosoCrew 服务的人可以预览。团队模板仅限来源团队的当前成员，成员可添加到自己拥有的空间。团队拥有者可以设置“允许公开”“仅团队”或“关闭分享”；个人空间提供公开与关闭两个选项。本项目默认团队仅团队、个人允许公开，不声称这是原产品所有部署的默认策略。

收紧策略会撤销不再允许的已发布链接。之后放宽策略不会恢复旧链接，需要重新发布。删除来源 Bot 后，模板仍可从“我的模板”管理和撤销；来源空间或模板创建者不可用时，已发布链接不可读取。

当前本机服务生成的链接只适用于能连接该服务的设备。它不代表模板已经部署到互联网。

## 存储与恢复

中央模板保存在 `platform/bot-templates.sqlite`，与账号、每空间工作数据分开。公开读取只访问中央目录，不为来源空间启动 Pi 或例行任务。草稿与不可变发布快照分别保存，已撤销的链接保留失效记录。每空间最多 100 份模板，草稿与当前发布版本合计最多 256 MiB。

同空间复制和跨空间导入共用同一安装流程。新 Bot、私聊、技能、例行任务、头像和操作回执作为同次目标空间操作保存；技能文件导出失败会回滚，已提交但收尾失败可以用原回执确认。未知结果保留原请求编号，先检查状态，再明确继续同一次请求，避免重复创建。

来源聊天中的模板卡只显示名称、分享范围和发布状态，不包含完整私有草稿。卡片是中央模板的同步视图，不声称两个 SQLite 数据库之间存在原子事务。写入卡片失败会标记待同步，允许显式重试；普通读取不会偷偷修复或创建聊天。卡片固定标识和递增版本，旧结果不能覆盖新状态。

私有接口绑定实际登录账号、空间和当前拥有者权限，不接受正文指定的身份。公开接口携带期望账号时校验登录匹配；没有期望账号的请求按匿名处理。团队头像也按固定账号读取，避免另一个窗口切换登录后让旧页面读取新账号的私有内容。

## 验收状态

2026-11-05，[真实 HTTP 验收](evidence/bot-template-http-20261105.json)使用临时个人及团队账号，完成复制、草稿编辑、公开与团队发布、导入、服务重启和撤销。检查了真实 Pi 技能文件、原样头像图片、明确的例行任务状态，以及历史、记忆与附件不进入副本；收紧策略和移除成员立即生效，已完成导入可在原链接撤销后恢复回执。临时数据已清理，没有调用付费模型、修改正式用户数据或操作远程电脑。

[完整检查](evidence/bot-template-verification.json)最终覆盖 547 项服务端与 205 项前端/桌面验证，2 项仅 Linux 适用的检查跳过。十项浏览器引擎补测首轮 9 项通过，普通下载点击后的导航等待在并发运行时超时，原样单项重跑通过；没有改动电脑代码或扩大超时来通过检查。一个原有发送测试改为等待真实请求与结束事件，修复依赖固定轮次等待的不稳定性。类型、34 个变更文件的格式及生产构建通过。[新版本机入口检查](evidence/bot-template-service.json)通过 26 项检查，原有正式数据基线保持不变。

七个原创模板的同源目录通过 Web 与 Flutter 一致性检查。320px 中文和 390px 英文界面测试覆盖筛选、查看、编辑创建和保护未保存的资料。公开与团队模板链接的历史验证见上述记录，当前客户端范围见[验收记录](verification.md)。
