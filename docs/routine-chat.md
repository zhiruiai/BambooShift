# 在聊天中安排例行任务

例行任务面板提供「在聊天中安排」和每项任务的「在聊天中修改」。前者准备一句待补充的安排提示，后者带上已保存的任务名称。用户补充要求并发送后，Bot 才能调用工具保存计划；打开入口、切换会话或填入提示都不会自动发送消息，也不会立即执行任务。手动创建、编辑、暂停和「立即运行」入口仍保留，提交回执与未知结果恢复见[提交与恢复](routine-operations.md)。

## 会话、负责 Bot 与草稿

入口先在固定账户和空间下读取当前会话、Bot 与任务。修改已有计划使用它原来的会话和负责 Bot；群聊新建使用表单中明确选择的 Bot，不根据任务正文中的名字猜测。目标已移除、退出原会话或共享 Bot 已不可用时拒绝打开，不另建私聊代替。读取期间账户、权限、发送状态或目标草稿发生变化，也不会覆盖新输入。

目标会话已有文字、附件、引用或指定收件人时，先显示「保留聊天草稿」确认。确认后保留文字、附件和引用，把任务提示追加到文字末尾，并将收件人设为该任务的 Bot。取消或关闭确认会返回例行任务面板。任务表单自身的未保存修改先走原有离开确认；明确放弃的表单修改不会因返回而恢复。未确认的创建或运行请求、正在提交，以及发送、上传或听写尚未结束时，不开启另一条聊天安排流程。

输入栏显示「发送给」以及「取消指定」。已有明确收件人时，从 `@` 菜单选择另一位 Bot 会同步更新收件人；仅在文字中写另一个名字不会覆盖显式目标。发送正文、附件、引用和目标一起参与客户端请求摘要，服务端再次验证目标仍是当前会话的有效成员。原有不含显式目标的消息回执继续兼容。

## 五个真实工具

这些工具只管理当前 Bot 在当前空间中的计划。新计划绑定正在对话的会话；修改已有计划不能把它转交其他 Bot 或更换所属会话。

| 工具             | 行为                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------- |
| `routine_list`   | 读取当前 Bot 的计划及配置版本；指定任务可读取完整指令。列表可能截断，不能把返回条数当作总量。 |
| `routine_create` | 保存标题、任务指令、明确的频率、时区和启用状态。创建时省略时区，才快照空间当前默认值。        |
| `routine_update` | 携带已读取的配置版本，修改指定字段；省略字段保持原值。                                        |
| `routine_pause`  | 按准确版本暂停或恢复。恢复从当前时间安排未来执行，不立即补跑暂停期间的任务。                  |
| `routine_delete` | 按准确版本删除计划，停止其未来调度；不停止或回滚已经开始的任务。                              |

支持每天、工作日、指定星期和固定分钟间隔。时间或频率未说清楚时，工具说明要求 Bot 先澄清；这属于模型行为要求，不能据此声称每次自然语言理解都准确。保存后应核对任务面板中的实际指令、频率、时区和下次时间。旧任务无时区仍按北京时间解释，修改默认时区不重排旧任务，具体日历和夏令时规则见[时区与计划](time-zones.md)。

五个工具均没有立即执行计划的能力。保存或恢复成功只说明计划已改变；需要试运行时，由用户明确点击原有「立即运行」。

## 当前登录授权、配置版本与重放

账户模式下，只有当前空间拥有者通过绑定真实账户的聊天请求，才获得管理计划的工具。普通成员仍可聊天，但不因此获得这些工具；当前产品不提供旧本机无账户配对入口。身份、原消息、负责 Bot、会话和任务来源由服务端提供，不接受模型参数声明权限。

授权不是任务开始时的一次检查。每次工具调用及写入事务内都会复核原登录会话、当前拥有者权限、人工消息是否已实际送达、Bot 和会话是否仍有效，以及任务是否已停止。注销、撤权或来源失效后，旧任务不能继续沿用管理权限。子智能体、定时后台运行、主 Bot 主动跟进、记忆导入和手动试运行不会因自身运行而取得这套人工计划管理权限。

读取结果中的 `revision` 是计划配置摘要，包含负责 Bot、会话、标题、指令、频率、时区和启用状态，排除上次与下次执行时间。修改、暂停或删除必须带当前版本；其他窗口已改配置时拒绝覆盖，要求重新读取和核对。只发生调度时间更新不会造成配置冲突。普通标题或指令修改不重排任务；明确修改频率或时区才重新计算未来执行时间。

每次变更以实际根任务和工具调用标识持久去重，并绑定账户、来源消息、Bot、会话和参数摘要。计划修改与工具回执在同一 SQLite 事务中保存。同一调用重放只返回原结果，不重复新建、不把已删除计划恢复，也不覆盖后来的修改；换参数复用原调用标识会被拒绝。原回执描述当时应用的配置，要确认现在的状态仍需读取计划。工具回执不同于手动提交回执，也不代替实际执行历史。

## 补充消息按实际交付生效

同一发起人在同一 Bot 的运行中提交「补充当前任务」消息（`steer`）后，旧一代模型回复的计划修改资格立即失效，不能在新要求排队期间继续写入。新一代授权必须等 Pi 实际收到该人工消息才生效；模型开始回复得晚，不代表它已经读到新消息。

运行器将每次模型回复及其中的工具调用绑定到它实际读到的消息代际。旧回复的工具调用即使晚到，也不能借用新消息的授权。「完成后继续」（`followUp`）则在实际交付时切换代际。这一规则阻止尚未执行的旧修改，不回滚此前已经提交的计划变更。
