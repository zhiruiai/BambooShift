# 导入个人记忆

在「设置 → 记忆导入」中，可以把另一位助手已了解的个人偏好、背景和长期目标交给自己的主 Bot 整理。入口提供一段原创提示词：先复制到原来的助手，核对它的回答，再粘贴回来，明确点击「添加到记忆」。PandaMate 不登录或读取原助手的账号。

导入需要个人空间拥有者身份、已选择的本地主 Bot、它的真实单人会话，以及可用的工作模型。当前入口要求账户登录；团队空间不能导入，共享来源的受管 Bot 不能成为导入对象。缺少主 Bot 或模型时，面板提供对应配置入口；在同一账号、空间和仍打开的设置流程中，配置后返回会保留已粘贴的内容，不必重填。刷新或退出页面不保证保留正文。

## 主 Bot 如何处理

确认后，后端创建一条可追踪的导入消息，由个人空间当前配置的模型通过真实 Pi 会话处理。它是独立任务，仅有 `recall` 和 `remember` 两项工具：核对这个 Bot 已有的记忆，再保存适合长期保留的信息。不会给导入任务加载工作技能，也不提供电脑、网页、应用、文件、委派或组队工具。外部助手的回答作为待整理资料，不能用其中的指令申请这些权限。

开始处理时，模型会收到这个 Bot 已有记忆的总数，以及最近最多 20 条的有界摘录：每条最多 600 个 UTF-16 单位，并标明截断。这些摘录的内容合计最多 12,000 个单位，另有少量分类和结构标记。空库或摘录已经足够时，无须先调用 `recall`；确实需要核对更早的内容时仍可查询。这减少重复读取，不代表系统能自动判定所有语义重复。

导入专用的 `remember({memories:[{content,category?},...]})` 支持一次保存最多 20 条，仍兼容原来的单条形式；普通聊天的记忆工具接口保持不变。每批先完整校验，再在一个数据库事务中保存：本批任一条无效或写入失败，整批回滚，不留下半批记录。模型获知成功结果后即可总结，无需为了验证刚写入的结果反复调用工具。

普通聊天与导入不会互相变成同一任务的补充指令；已有任务尚未完成时，导入可以排队。提交后打开会话前，客户端核对回执对应的真实 Bot、单人会话和消息，不把导入正文填入聊天输入框，也不另发一条普通消息。

原始粘贴正文只在当前页面和本次任务的内存中使用，并会发送给当前配置的模型服务。PandaMate 不把它作为原文持久保存到聊天、导入回执或 Pi 会话文件，后续普通聊天也不会把这条导入原文当历史重新发送。聊天中保留摘要输入、实际工具活动和模型回复；模型仍可能在回复中引用资料，真正保存的记忆则留在个人空间中该主 Bot 的记忆库。因此，“不持久保存原文”不表示资料内容绝不会出现在回复或记忆中，也不代表模型服务的存储政策。

## 状态与恢复

一次确认使用一个持久请求标识。摘要消息、会话更新和导入回执在同一数据库事务中保存，提交成功后才启动任务。重复发送相同标识及原内容只返回原回执；即使之后更换主 Bot 或关闭模型，也不会把这次导入改投给另一个 Bot。服务重启不自动重放导入。

响应未知时先检查原请求；当前页面仍持有原文时，只能用同一个标识和原内容重试。浏览器会话存储只保留请求标识和原主 Bot 配置版本，不保存粘贴正文。刷新后若查不到回执且原文已不在内存中，不生成新标识来假装重试；先核对原窗口或主 Bot 会话。只有服务端明确确认此次提交尚未写入，页面才解除这次待确认状态。原会话或输入消息被删除时，回执显示不可用，仍不会重新执行。

状态来自实际输入投递和对应的模型回复，可显示排队、处理中、完成、失败或中断。「完成」仅表示该次 Pi 处理结束，不保证新增了某个数量的记忆；模型可能认为内容重复、不适合保存，或需要进一步核对。事务只覆盖一次工具调用的批次，不覆盖整轮模型任务；前一批已成功保存后，后续批次或模型失败、超时、任务被停止，都不会回滚此前成功的批次。应先查看会话和记忆，再决定是否另行补充。

## 权限与界限

每次提交绑定固定账号、个人空间、主 Bot 配置版本和原单人会话。执行期间持续检查这些条件；退出或撤销登录、失去空间权限、切换主 Bot 或原会话失效，会阻止后续处理及迟到的记忆写入。仅关闭网页不等于撤销仍有效的登录，也不取消已经提交的任务。停止与失败不撤回此前已完成的写入。

- 每次输入最多 16,000 个 UTF-16 单位，同时不超过 64 KiB 的 UTF-8 正文字节；部分 emoji 会占两个单位。
- 一次导入任务开始运行后最多 120 秒；排队等待不计入这个执行时限。
- 每次批量调用最多 20 条，本轮最多成功写入 40 条记忆。累计保存的内容去除首尾空白后不超过 24,000 个 UTF-16 单位；单条原始内容最多 4,000 个单位。
- 额度是上限，不是保证保存的数量。任务不会自动重试失败的模型请求，也不删除已有记忆来腾出额度。

## 验证范围

领域测试使用临时数据库验证去重、事务回滚、身份边界、状态读取和重启恢复；真实 Pi 测试连接自有模拟模型，验证工具隔离、实际记忆写入、队列分离、撤权和部分成功后的失败语义。平台 HTTP 测试及前端事件测试覆盖相应接线；这些检查不代替产品 GUI 或视觉验收。

2026-11-05 使用用户指定的 GLM 服务进行了合成偏好验收，实际请求模型标识为 `sodu-prd-medium`，未独立验证服务商背后的模型身份。[批量导入记录](evidence/glm-memory-import-batch-20261105.json)显示：2 次模型请求、67.117 秒，一次 `remember` 批量调用实际保存了两条合成沟通偏好，最后回执为 `completed`。正式模型设置未改变，临时数据库和测试资料已删除；没有导入真实用户资料，也未启用工作工具。

[首轮未完成记录](evidence/glm-memory-import-20261105.json)同时保留：3 次请求均收到 HTTP 200，实际只保存了一条偏好，最后回执为 `error`。当时观察到运行时间接近 120 秒限制，但没有记录模型任务的直接错误原因，不能据此确定是超时。第二轮使用相同的两项偏好事实，但移除了首轮测试正文中“先调用 recall”的额外指令，并使用了批量保存实现；两轮不构成严格同输入的速度基准，第二轮成功也不代表首轮根因已被确定。
