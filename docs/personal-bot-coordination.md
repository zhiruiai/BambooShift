# 个人主 Bot 的身份与协作

Rust 执行入口会向实际 Pi 会话提供当前 Bot 的 ID、姓名、角色、简介、长期指令和配置版本，并把同事目录与自身身份分开。角色和长期指令是拥有者保存的工作配置，不能授予权限、替换请求账号或绕过审批。当前任务使用固定配置快照；同一次协作再次调用同一 Bot 时保留该快照，新的人工任务读取最新配置。

个人空间的拥有者在已选主 Bot 的固定私聊中发起人工任务时，主 Bot 可以调用 `list_peers` 和 `delegate`。候选是同一空间中有合法单人会话的本地 Bot；目标私聊由服务器选择，模型不能指定其他会话、空间或账号。没有可用私聊时拒绝委派，不自动创建新会话。共享引用、团队 Bot、非主 Bot 的普通私聊、后台任务和子任务均不会因这条入口获得跨私聊委派权限。

目标 Bot 在自己的私聊执行，读取自己的聊天历史、记忆和已启用技能。主 Bot 私聊保存委派活动及实际返回结果，不复制目标的完整历史。目标私聊收到新的人工消息时先排队，等实际子进程结束后再开始独立任务。群聊仍只允许本轮名单中、且目前仍在群内的成员互相委派。

子任务继承原人工请求者、会话授权、模型配置快照、取消信号和协作额度。应用操作仍由原请求者审批；电脑操作仍受逐次审批、人工接管和按 Bot 的任务锁约束。父任务停止、原登录失效、拥有者资格失效，或者来源／目标私聊身份变化后，旧子任务和迟到结果不能继续执行。已开始的外部操作不承诺回滚。切换主 Bot 会阻止旧主 Bot 发起新的私聊委派，但不会仅因切换配置就停止已接纳的普通人工工作。

这项变化不包含录制人工操作生成技能、不自动授予应用权限，也不改变已有群聊负责人或共享来源的隐私边界。

## 验证范围

新增 Rust 测试使用真实 Pi 子进程、本机模拟模型和 MCP 服务、临时账号与数据库，覆盖配置下一轮生效、身份不串用、目标私聊实际执行、历史隔离、子任务结果投影、原请求者审批、取消和撤权后的迟到工具拒绝。它们不调用真实付费模型，不访问正式资料或远程虚拟机；不能代替产品界面的视觉验收。

相关文件为 `server/api/tests/agent_primary_delegation.rs`、`agent_primary_authority.rs`、`agent_primary_apps.rs`，并与既有群聊委派、共享来源撤权及消息队列测试一起回归。
