# 在知乎写一篇技术文章

进入所选 Bot 的单聊，说「把这份公开的 CSV 核对报告写成知乎技术文章，给出复现步骤和实测数字，先保存到知乎草稿」。Bot 可以从当前工作空间查找知乎的创作入口和内置写作流程。只想先在聊天里审稿时，可以说「先交付 Markdown」，Bot 会把工作文件交回单聊。

需要固定使用某个工作流版本时，可在 Bot 设置中打开 **选择与管理技能 → 从技能库选择 → 知乎技术文章 → 安装技能**。点 **完成** 可看到已启用的版本，也可以在单聊中输入 `/` 选用它。包内有 `SKILL.md`、技术文章模板、编辑与回执清单，以及核对文章链接格式的离线脚本。

## 从草稿到发布

1. **进入自己的编辑器。** 使用已授权工作电脑上的浏览器打开知乎写文章页，也可从知乎首页右侧的「创作中心 → 写文章」进入。隔离浏览器有自己的登录状态。第一次登录或遇到验证码时，请私密接管并自行完成，然后将控制权交还 Bot。要沿用 Mac 上已有的浏览器会话，可以选择「电脑 → Mac 应用」操作当前窗口。所需控件能否被读取或填写取决于浏览器向辅助功能公开的内容。[知乎科技创作者指南](https://event.zhihu.com/tech-creator-guide/) · [知乎文章编辑器](https://zhuanlan.zhihu.com/write) · [电脑设置和人工接管](computer.md)
2. **检查成稿。** Bot 根据编辑器当时显示的控件分别填写标题和富文本正文。浏览器的输入回执会报告字段读回是否一致。段落、代码块和来源链接还需在编辑器预览中核对。页面确认草稿已保存后，才报告「已存草稿」。已交付的 Markdown 可在编辑器不可用时继续使用。
3. **确定发布内容。** 用户可以指定目标账号、文章定稿和可见范围，明确要求发布。已有这项授权即可继续。仅要求草稿、正文有实质变更或页面要求的原创声明尚未确认时，Bot 会先请用户决定。工作电脑的「完全授权」会复用电脑操作权限，文章具体发给谁、发哪一稿仍取决于用户给出的任务。
4. **核对文章链接。** 最终提交一次后，Bot 在内容管理或正式文章页核对标题、作者和状态，并把实际看到的文章直链带回原聊天。知乎专栏文章链接通常为 `https://zhuanlan.zhihu.com/p/<数字标识>`。处于审核中时交付审核状态，提交失败时交付页面原因。若提交后响应丢失，先查看内容管理再决定是否重试。包内 `scripts/article_link.mjs` 只做地址格式校验，发布结果以该账号的实际页面为准。

可从「连接应用 → 发布账号」选知乎和所需 Bot，进入其工作电脑，在浏览器画面点「私密接管并打开登录页」。同一工作浏览器保留网站登录。团队中可以接管它的成员和共用此浏览器的 Bot 都可能使用该会话，建议使用团队发布账号。首次准备电脑需要工作空间拥有者。

## 验证范围

官方创作者指南给出了桌面入口。未登录访问写文章页会转向登录。仓库中的 Chrome 测试在隔离环境中拦截并响应测试页面的全部请求，验证了双字段填写、富文本读回、草稿和最终提交的区分、发布直链、审核中与失败，使用虚构的账号与文章。真实账号的登录、编辑器版本差异、审核以及公开文章发布需要在目标账号上验证。[浏览器验收代码](../server/workers/computer-runtime/tests/zhihu-article.browser.test.ts)

运行下面的测试需要 Node.js 22.19 或以上版本和已安装的 Chrome。将 `CHROME_EXECUTABLE` 指向执行电脑上的实际可执行文件。下面以 macOS 为例。

```sh
OPENBOT_BROWSER_TEST=1 \
CHROME_EXECUTABLE='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
node scripts/run.mjs --test server/workers/computer-runtime/tests/zhihu-article.browser.test.ts
```
