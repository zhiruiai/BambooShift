# 独立运营平台

运营平台是供运营人员使用的独立站点，负责查看、停用和恢复平台用户及工作空间。普通用户的注册、聊天、Bot 设置和团队协作仍在产品站点。运营登录不会赋予普通账号运营权限，产品退出也不会退出运营会话。

截至 2026-11-06，独立入口的代码、自动化检查、临时整包与真实浏览器验收已通过。本机产品与运营站点已分别在 5173 和 5174 运行；旧产品运营链接会跳到独立运营站点。[脱敏证据](evidence/operations-separation.json) 单独保存本轮结果，不改写此前重构验收数字。

## 入口与权限

| 项目          | 产品站点                     | 运营站点                                                 |
| ------------- | ---------------------------- | -------------------------------------------------------- |
| 开发页面示例  | `http://127.0.0.1:5173`      | `http://127.0.0.1:5174`                                  |
| Rust 监听示例 | `127.0.0.1:3001`             | `127.0.0.1:3002`                                         |
| 页面入口      | 登录、注册、个人与团队空间   | `/`、`/admin`、`/admin/login`、`/admin/setup` 及运营页面 |
| HTTP 接口     | 账号、工作空间及业务执行接口 | `/api/platform/*` 与健康检查                             |
| 静态产物      | `runtime/dist`               | `runtime/operations-dist`                                |
| 会话          | `account`                    | `operator`，另需有效运营角色                             |

两个监听器位于同一个 Rust 进程，共用一个 `State`、身份数据库、调度器和关闭流程，没有启动第二个业务数据写入服务。运营页面是独立构建入口，不通过产品页面内的隐藏路由提供管理权限。

产品监听器不提供运营 API；运营监听器不提供账号注册或工作空间执行 API。两站独立核对 Host 和 Origin，运营入口不会自动信任产品开发页面的来源。即使浏览器在同一主机的不同端口携带两个 Cookie，服务仍按会话用途与角色核验；普通账号 Cookie 改名或使用普通账号正确密码，都不能取得运营权限。

## 配置与启动

私有服务配置新增可选 `operations`：

```json
{
  "bind": "127.0.0.1:3001",
  "webOrigin": "http://127.0.0.1:5173",
  "operations": {
    "bind": "127.0.0.1:3002",
    "webOrigin": "http://127.0.0.1:5174"
  }
}
```

这是入口配置片段。完整占位示例见 [本机配置](../server/api/config.example.json) 和 [部署配置](../server/api/deployment/server.example.json)。部署时两站分别配置 HTTPS `publicOrigin`；Rust 继续监听本机，由同机代理提供外部 HTTPS。运营 Cookie 是否使用 `Secure` 和 `__Host-` 名称由运营入口自己的 HTTPS 配置决定。

产品的旧 `/admin` 路径仅向已配置的运营 `publicOrigin` 或 `webOrigin` 返回 307。目标来源不从请求 Host 推导；缺少可用运营目标时返回 404。产品静态服务不会读取运营产物。两套静态读取均保留逐级拒绝符号链接及文件类型、大小限制。

启动先占用两个监听地址，再初始化数据库。任一地址被占用时不进行数据库初始化或生成运营初始化码。就绪事件保留产品 `address`，启用运营入口时增加 `operationsAddress`；显式配置了运营页面来源才给出 `operationsWebOrigin`。停止信号会关闭两个监听器、等待业务清理并释放同一数据目录写入锁；启动期间等待初始化时收到停止信号，也不会继续生成初始化码。

## 已验证范围

- Rust 全量 236 项通过、0 失败、0 跳过，覆盖 75 个测试目标。独立入口定向 16 项已包含在其中，不重复加总。
- Web 全量 425 项通过；TypeScript 无错误，产品与运营两套构建通过。
- 启动与装配 9 项、装配检查器合同 11 项通过。实际完整包在两个随机本机端口运行，验证两站页面、双向 API 隔离、账号权限、会话隔离和正常关闭；数据为临时合成账号，本机合成模型不涉及真实用户内容。
- 本机调试产物共 106 个自有文件、38,785,528 字节；离线清洁安装 228 个生产依赖。整包验收未消费运营初始化码，也没有执行正式切换。
- 本机双入口健康检查、双向 API 隔离、来源拒绝与旧链接跳转均已确认。临时虚构账户完成产品注册、运营初始化、全平台列表、停用及恢复用户的实际操作；运营页最小可见字号为 12px，没有产品导航链接。临时服务和资料已清理。本轮没有新增移动构建、模型账号或远程电脑验收。
