# Bot 头像

头像选择器保留六个原创形象与颜色，也可上传自己的图片。Bot 创建、设置、主 Bot 创建和智能组队的新成员使用同一选择器；聊天、侧栏、群头像和成员列表使用同一个展示组件。

## 上传与裁剪

选择或拖入 PNG、JPEG、WebP 图片，服务端检查实际格式并校正照片方向，再返回预览。用户可以移动图片、调整缩放，用方形裁剪区域确定头像；坐标按纠正方向后的图片计算，最终裁剪由服务端执行，统一输出 512 × 512 WebP。文件要求小于 25 MiB，不支持动画或把 SVG/网页内容当作图片。

点击确认裁剪只把图片加入当前 Bot 编辑草稿，保存 Bot 设置或确认创建才生效。取消会保留原头像。用户可以切回原创形象，原图不会被当作聊天附件发送给模型，也不会出现在 Bot 可读的工作文件目录。

上传中切换账号、空间、关闭编辑器或选择另一张图片，会取消当前请求并忽略迟到结果。裁剪成功也只更新头像字段，不用上传开始时的旧资料覆盖期间修改的名字、角色或指令。完整资料保存仍检查 Bot 配置版本。

## 资源与权限

原图暂存于当前空间的私有数据库中，仅拥有者可读取去除元数据的预览。原图最多 4,000 万像素；每个空间最多暂存 8 张、共 96 MiB，1 小时后不能再读取或裁剪。取消、换图和确认裁剪后会尝试释放已知原图，账号或空间切换不会跨身份补发清理；过期原图在下一次成功上传事务中惰性删除，不能把逻辑过期说成准点物理擦除。最终头像使用本空间生成的不可变标识，不保存外部 URL。裁剪后的未保存图片只有拥有者能预览，正式保存后成员才可读取。

创建或保存 Bot、创建主 Bot、编辑和确认团队方案均校验头像资源属于当前空间。模型提出团队方案时不允许指定图片标识；用户仍可在方案编辑器为新成员上传头像。公开发布头像与保存 Bot 配置在同一事务中完成，失败不留下“资料没保存、图片却已公布”的中间状态。

替换头像不会覆盖旧图片文件；删除 Bot 后，保留的群聊作者快照仍能显示其头像。最终图片每个空间最多 512 张、共 64 MiB，包含尚未保存到资料的裁剪结果，不通过未经验证的引用清理删除历史资源。浏览器读取使用当前空间的受认证接口，不允许从另一空间或任意图片 URL 取图。

## 参考与验收

交互参考官方 [Bot 头像说明](https://docs.x.ai/grok-bot/bots) 的形象选择、上传与裁剪。本轮只实现原创形象和上传；图片生成功能仍待接入可验证的生成服务，不用静态图片或无效按钮冒充生成。

当前图片处理由独立的 Rust `openbot-image-worker` 执行，[图像处理实现](../server/api/src/workspace/avatar_codec.rs)校正 EXIF 方向和镜像，再输出不含原始元数据的 WebP。[进程管理](../server/api/src/workspace/avatar_jobs.rs)限制并发与截止时间，同时保留上传字节、解码像素和资源容量限制。旧验收记录中的 sharp 指迁移前实现，不是当前服务依赖。

2026-11-05，使用临时个人和团队账户实际调用上传、裁剪、保存、成员读取及跨空间拒绝接口；原始六角色图只裁出指定绿色角色，服务返回的 512 × 512 WebP 已在当时查看；旧输出图片不随源码导出。[HTTP 验收记录](evidence/avatar-upload-http-20261105.json)确认恢复原创头像、删除 Bot 后历史引用仍有效，临时数据已清理，未调用模型或操作远程电脑。

[2026-11-05 历史回归记录](evidence/avatar-upload-verification.json)：服务端 491 项、前端和桌面 148 项通过，2 项仅适用于 Linux 的检查跳过；类型、27 个变更源码的格式和生产构建通过。[本机服务检查](evidence/avatar-upload-service.json)通过 17 个页面与权限入口，原有数据基线未改变。

该历史批次的产品浏览器控制被工作设置拒绝，没有完成拖放、裁剪布局和手机触控验收。后续页面验收与当前回归范围见[验收记录](verification.md)；历史返回图片、事件测试和接口结果不代替产品 GUI 验收。
