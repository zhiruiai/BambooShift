# BambooShift 桌面端

打开应用后，可以在这台电脑创建个人工作空间，也可以连接已有的 BambooShift 服务。启动页会显示当前安装包提供的选项。

内置个人空间目前是开发预览。macOS Apple Silicon 的独立测试安装包已通过免登录启动、配置模型、真实文件交付、Markdown 预览、退出清理和重启后继续任务的验收。测试使用受控的合成模型服务，执行的是安装包内的真实 Pi 与文件工具，不代表外部模型质量或整机键鼠操作已经验收。原生图像依赖候选已配套校验过的对应源码和许可材料，尚未公开交付；其余平台的完整安装包仍待验收。缺少包级许可文本时构建会失败；这项检查不代替原生二进制的组件许可审查。自动发布继续提供连接客户端，尚未包含这项预览。

| 入口                 | 适合的用途                               | 任务运行位置                                                                     |
| -------------------- | ---------------------------------------- | -------------------------------------------------------------------------------- |
| **在这台电脑开始**   | 独立使用、调试技能、在当前电脑交付文件   | Electron 启动应用内置的 Rust 服务和 Pi 运行环境。退出应用时，本机任务停止。      |
| **连接已有工作空间** | 使用团队空间、自托管服务或已绑定的云电脑 | 任务由已连接的服务和选定的工作电脑执行。关闭客户端后，在线服务上的任务可以继续。 |

## 在这台电脑开始

1. 打开包含内置运行环境的桌面应用，点击 **在这台电脑开始**（**Start on this computer**）。个人空间直接打开，无需注册或输入账户密码。
2. 在 **设置 → 模型配置**（**Settings → Models**）保存模型服务地址、名称和 API Key，将该配置设为默认。
3. 在 Bot 单聊发起第一个任务。例如，让 Bot 把几条示例会议纪要整理成 Markdown，并在聊天里交付文件。工作区文件在当前电脑保存。模型请求会发到你选定的模型服务。
4. 想使用隔离浏览器时，在 **设置 → 电脑** 使用本机连接。浏览器功能需要在执行电脑上安装 Chrome，使用独立浏览器资料。公开网页搜索可以直接通过 Bot 的检索工具进行。

再次打开应用会恢复上次选择的本机空间及已保存的模型配置。通过原生菜单 **空间 → 本机工作空间…**（**Workspace → Workspace on this computer…**）可查看本次运行方式，包括整机操作是否开启。打开或取消说明不会中断任务；明确选择 **返回启动页调整** 才会停止本机任务，已保存的对话和文件保留。如果当前连接的是已有服务，返回启动页只断开客户端，服务上的任务继续运行。

### macOS 整机操作

1. 在启动页勾选 **允许整机操作**（**Allow computer control**），再启动本机工作空间。此选项默认关闭。包含 Cua Driver 的 macOS 构建会显示此选项。
2. 使用主屏上的原生应用时，在聊天的电脑面板选择 **整机桌面**。如面板提示权限缺失，在 macOS **系统设置 → 隐私与安全性** 为系统列出的应用开启 **屏幕与系统音频录制** 与 **辅助功能**，然后按面板提示启用桌面范围。
3. Bot 请求点击、输入或运行终端命令时，在聊天中查看并批准具体操作。终端使用当前系统账户的权限，命令可访问该账户可访问的文件和网络。操作前请核对命令和起始目录。
4. 关闭整机操作时，从原生菜单返回启动页，取消勾选并重新打开本机空间。macOS 系统权限可在系统设置单独撤销。

整机画面当前覆盖 macOS 主屏。使用视觉模型观察桌面时，截图会发给配置的模型。终止命令可停止仍受执行器管理的进程，已经发生的更改会保留。开发验证覆盖了官方驱动启动、私有套接字和退出清理。真实屏幕读取、键鼠输入还需要在获准的 macOS 桌面会话验收。

## 连接已有工作空间

输入服务的 HTTPS 地址。已经单独启动在当前设备上的服务，可用 **填入本机地址** 填充建议地址。客户端检查服务健康状态，再打开该服务的登录页面。个人和团队空间继续使用该服务的账户。

连接成功后客户端会记住服务地址，下次启动尝试连接一次。失败时可重试或更换地址。不同服务使用隔离的浏览器会话，本机个人空间也有单独的会话。已连接服务需要云电脑时，请在 **设置 → 电脑 → Bot 的电脑** 查看部署者已绑定的云电脑，或连接运行在另一台电脑上的专用 Worker。本机个人空间不会自动注册成其它服务的远程执行设备。 [执行位置与配对](computer.md#选择执行位置) · [部署指南](../server/api/deployment/README.md)

### Windows x64

从 [GitHub Releases](https://github.com/zhiruiai/BambooShift/releases) 下载 Windows x64 客户端 ZIP，完整解压后运行 `BambooShift.exe`。输入已有服务的产品地址。Windows 便携包尚未做发行者签名，可用发布页的 SHA-256 校验归档。服务部署和 WSL2 本地试用见 [Windows 连接说明](../server/api/deployment/README.md#connect-from-windows)。

Windows 的自动发布检查覆盖启动、语言切换和连接测试工作空间。独立浏览器在服务选定的工作电脑上运行。Windows 整机屏幕和键鼠适配尚未提供。

### macOS 签名

目前发布 ZIP 使用本地 ad-hoc 签名和严格资源校验。Developer ID 签名、Apple 公证和自动更新尚未配置。 [Electron 应用打包](https://www.electronjs.org/docs/latest/tutorial/application-distribution)

## 从源码构建与验证

安装稳定版 Rust、Node.js 22.19 或以上版本（推荐 24）和 npm。在仓库根目录运行下列命令。

```sh
npm ci

# 开发预览：在当前 macOS 或 Linux 架构验证内置服务打包
# 依赖许可材料不完整时，严格检查会停止构建
npm run client:package -- --with-runtime

# 启动连接客户端开发版
npm run client:dev

# 运行桌面端测试
npm run client:test
```

构建产物和对应平台清单位于 `release/client/`。默认不带 `--with-runtime` 的打包命令生成连接客户端。使用 `--platform darwin|win32|linux` 和 `--arch arm64|x64` 可明确指定目标，`--dry-run` 只显示计划。内置运行环境要求在目标系统和架构上构建。

本机运行环境包含 Rust 服务、Node.js、Pi Worker、电脑和文档 Worker、MCP Worker 以及网页产物。macOS 内置运行环境还包含固定版本的 MIT Cua Driver。打包以源码、锁定的生产依赖和经校验的公开上游二进制为输入。应用生成的本机个人空间、账号信息、模型密钥和浏览器资料位于客户端用户数据目录。 [架构](architecture.md#desktop-and-cloud-execution) · [运行时打包](../scripts/desktop/runtime-package.mjs) · [第三方许可](../THIRD_PARTY.md)

桌面运行环境只从 PDF 提取文字，不包含 PDF.js 可选的原生 Canvas 光栅化依赖。安装时为目标系统和架构保留精确版本的 Sharp 与 libvips，PNG、JPEG、WebP 解码、方向校正和图片限额保持完整。依赖版本升级必须通过无原生 Canvas 的 PDF 验收；新出现的可选能力会阻止打包，直到完成审查。省略未使用的渲染依赖不替代其余原生库的许可检查，正式内置包仍须通过完整的分发验收。

macOS arm64 已有包含独立构建图像库、完整许可文本及对应源码归档的完整候选包，并通过实际安装包验收。可用显式的 `--native-image-candidate` 参数构建；它仍标记为未批准发布，不改变默认客户端或自动发布。原官方 npm 二进制的审查记录保持独立，其余平台仍需分别完成材料和验收。`proxy-agent-negotiate@1.1.0` 的确切上游 MIT 声明已核实并保留。[候选包构建、来源记录与验证范围](native-image-runtime.md)

验证界面时可先用开发客户端连接测试服务，再用 `--with-runtime` 构建验证免登录、本机文件交付和退出清理。原生菜单 **帮助 → 键盘快捷键** 显示当前客户端快捷键。连接页和原生菜单支持简体中文及英文，网页工作空间语言由其自身设置管理。

### 已验证的个人模式流程

[2026-11-13 验收记录](evidence/desktop-personal-runtime-20261113.json)覆盖 macOS arm64 的完整应用包：从空白资料目录打开个人空间，在界面配置受控模型，使用包内 Pi 创建并交付 Markdown，退出应用后确认后台结束，再次打开后使用原配置完成第二次交付。原文件、对话和中文预览均保留。

本次还修复了附加运行环境复制时将 npm 相对工具链接改写为构建机绝对路径的问题。运行环境在签名前独立复制，保留相对链接并拒绝指向包外的链接。严格签名校验和移开构建源后的包内 Pi 启动均通过；安装包不依赖构建电脑上的 npm 目录。

该测试候选保留了尚未完成的原生许可清单，仅用于隔离的本机验收，没有进入自动发布。录屏、键鼠授权及操作、外部模型效果和其他平台的内置包仍需分别验收。

[安装包内本机命令验收](evidence/desktop-shell-approval-20261113.json)另经正常个人会话与电脑审批接口确认：待批准命令不执行，批准后输出、退出码和新建测试文件内容正确；拒绝不创建文件，非零退出码保留在结果中。仅使用合成数据，测试目录和临时会话均已清理。这是实际安装包的命令链路验收，不包含键鼠界面操作，也不替代新版进程组停止逻辑的独立验证。
