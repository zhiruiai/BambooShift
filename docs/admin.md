# 平台运营与空间管理

平台运营、产品账户与空间管理是不同的权限边界。平台身份与成员关系存在 `data/platform/identity.sqlite`，业务数据、Pi 会话和电脑状态由每个空间独立持有。

产品站点为 `http://127.0.0.1:5173`，独立运营站点为 `http://127.0.0.1:5174`。下表的 `/admin` 路径仅属于运营站点；其他路径属于产品。运营页面单独编译、登录，不提供个人/团队注册、聊天或空间管理入口。产品页面不显示运营入口，旧产品 `/admin` 链接只按私有配置跳转到运营站点。

| 入口                      | 用途与权限                                                                           |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `/login`、`/register`     | 产品账户登录、个人注册或创建团队；每个账户始终拥有自己的个人空间                     |
| `/invite/:token`          | 查看邀请，登录后明确加入；邀请七天有效且只能使用一次                                 |
| `/w/:workspaceId`         | 对应个人或团队空间的 Bot、会话、资料与工作电脑                                       |
| `/account`                | 本人资料、密码和登录设备，不依赖空间 owner/member 角色                               |
| `/w/:workspaceId/members` | 团队成员、邀请和简单管理；拥有者可邀请、撤销和移除成员                               |
| `/w/:workspaceId/manage`  | 空间拥有者的七分区管理页：概览、同事/会话、运行记录、模型、电脑、任务/技能、登录设备 |
| `/admin/login`            | 独立平台运营登录；产品登录 Cookie 或团队拥有者身份均不能代替                         |
| `/admin`                  | 全平台真实用户/个人空间/团队统计、搜索分页、账户与空间停用/恢复                      |

平台不因管理员身份自动提供私聊内容、模型密钥或冒充用户功能。停用账户立即撤销其所有会话；重新启用不会使旧会话复活。停用空间会关闭其任务、电脑与实时连接。移除成员立即关闭其对应空间 SSE，后续 HTTP 请求也会拒绝。

任务始终绑定真实发起者与原登录会话。停用账户或移除成员会使其授权失效，相关运行与待审批操作在权限复核时停止；其他成员自己的任务不因此变为可代批。已经发出的外部操作可能已生效，撤权不等于撤销外部副作用。

## 首次初始化与已有数据

首次明确使用 `--init-operator` 启动时生成本机 `data/platform/operator-setup-code`，权限 0600。在独立运营站点的 `/admin/setup` 输入这个初始化码，再选择管理员自己的邮箱、姓名和密码。码使用后删除，公开注册者不会变为管理员。运营和产品使用不同会话，管理员若要进入自己拥有的产品空间，也需在产品入口登录。普通启动不会替换初始化码。

旧版 `data/openbot.sqlite`、工作区文件、Pi 记录与电脑凭据仍留在原路径，身份库仅登记一个尚未认领的旧空间。只有受初始化码保护的首次管理员初始化能认领它。2026-11-05 切换本机预览前已备份到 `data/backups/pre-platform-20261104/`，并逐表比较消息、资料、模型配置等摘要，切换前后相同。这段备份描述属于 2026-11-05 历史迁移记录，不用于判断当前管理员是否已初始化。开源部署不包含默认管理员密码或正式账户。

## 界面与实现

三个层次共享 Avatar、UI 弹窗和按钮样式，模型/电脑/例行任务/设备继续复用已有组件。聊天和空间管理的技能正文共用 Markdown 渲染；运行记录链接包含消息 ID，可定位原文。手机使用真实账号菜单，普通成员的设置只显示自己的登录设备和权限说明，不读取模型管理数据。

团队仅有拥有者和成员两种角色，不提供复杂权限矩阵。成员共享团队会话、文件和工作过程；模型配置、电脑连接、技能批准与自动任务等管理操作由拥有者执行。消息作者由服务器绑定，回应按成员保存，取消自己的回应不会移除其他人的回应。个人空间不接受成员邀请。

本人姓名、密码和设备撤销写请求都带页面预期用户 ID，服务端只拿它与当前认证身份比较，不能据此切换身份；跨标签页切账号后旧页面操作会因身份不匹配被拒绝。设备查询也返回身份标识，前端先核对再显示。修改姓名不会改写既有消息的历史署名。修改密码需要原密码、新密码和当前有效会话，在事务中重新核对原密码哈希与会话，撤销本人所有产品/运营会话并关闭实时连接；旧密码验证结果在新密码生效后也不能再签发登录。对独立的其他运营身份没有影响。

密码修改网络超时只表示结果未确认，页面清除密码输入、提供重新登录核对，不自动重复修改。登录邮箱目前只作账号标识，没有验证邮件、邮箱修改或忘记密码找回流程。

已配置云电脑的状态可由空间成员查看，启动/恢复与连接管理仅由拥有者执行。平台运营身份不会绕过空间成员校验，也没有获得任意实例创建或控制入口。现有唯一云电脑只绑定原有空间，新注册空间不继承它。未复制的邀请链接不被下一次生成覆盖，关闭提示不等于撤销邀请；回应成员列表在流式回复中也保持不变。

数据 API 必须显式使用 `/api/workspaces/:workspaceId/...`，包括 SSE 与下载。切换空间会完整卸载旧页面，不依赖一个全局“当前空间”Cookie。运营接口使用 `/api/platform/*`，账户及团队成员接口使用 `/api/account/*`，均从服务端会话确定身份。

实际 Rust 主服务用两个独立监听器分别挂载产品和运营路由：产品不挂载 `/api/platform`，运营不挂载产品账户、团队和执行路由。两者复用同一身份存储、会话校验和业务服务，只运行一个调度器。部署时为两者配置不同 origin 与反向代理，运营来源白名单不包含产品站点；本地默认 API 端口分别为 3001 和 3002。各监听器只读取自己的 `dist` 或 `operations-dist` 静态树。

全平台列表专项检查覆盖运营人员无成员关系的个人账户、团队拥有者和受邀成员，普通产品身份不能访问运营数据。已有账户、团队与全局用户管理通过临时虚构账户的真实浏览器验收，详见 [重构验收记录](refactor-validation.md)。独立站点的入口、构建与权限验证单独记录，不把旧界面截图当作本次独立站点验收。

当前邮箱只是登录标识，没有声称已验证邮箱或发送邀请邮件。邀请通过生成链接分享；邮件验证、密码找回、SSO、计费、全平台共享模型额度及实际公网常驻部署尚未实现。
