# 配置发布账号

在桌面或网页工作空间的 **连接应用 → 发布账号** 选择创作平台和一个本地 Bot，打开它的工作电脑。准备「浏览器」画面，选择 **私密接管并打开登录页**。在网站核对账号、完成登录或扫码后，将控制权交还。账号会话留在这台工作电脑的浏览器中，网站可能要求重新验证。团队空间应使用团队账号，共用这台浏览器的 Bot 和有接管权限的成员可能都能使用该登录。

回到单聊就可以给任务。Bot 能按平台名找到工作空间保存的编辑器和内置发布指引。也可以将「知乎技术文章」「发布小红书图文笔记」或「跨平台内容发布」安装给指定 Bot，在聊天里用 `/` 选取。

> 把附件里的 CSV 核对报告写成技术文章，在知乎和 DEV 各存一份草稿。保留代码示例，把两个平台的保存结果分别发给我。

定稿后再说「用刚才确认过的团队账号，把这两份草稿公开发布」。如果其中一站还在审核，Bot 应分别回报两个平台的状态。若提交后网络中断，先到作品管理核对同一账号、标题和时间，再决定是否重试。

## 连接更多平台

工作空间拥有者可以选择 **添加自定义平台**，保存平台名称和官方的公网 HTTPS 创作地址。Bot 随后可按这个名称找到入口。同一平台管理多个主页时，任务中写清账号、组织、栏目及可见范围。平台的发布权限、开放接口和自动化规则仍然适用。新地址初次使用时，先存一份站内草稿，检查排版、署名和可见范围。

支持标准 MCP 且提供发帖工具的服务可在「连接应用」中配置服务地址、账号授权及所需权限，再使用其发帖工具。Discourse 已有建主题和回帖流程。[Discourse 配置步骤](app-connections.md#discourse-论坛发帖)

仅提供手机编辑器、要求专用上传协议、或限制自动化的平台，能完成的步骤会随账号和内容类型变化。目前浏览器的附件操作支持单次选择一张图片，视频、音频和直播需要相应的平台接入。扫码、验证码和实名由账号持有人在私密接管中处理。

## 怎样判断帖子已经发出

| 平台给出的证据 | 聊天中应回报的状态 |
| --- | --- |
| 编辑器确认保存，或作品管理显示草稿 | 已存草稿，可附草稿管理链接 |
| 平台显示审核中，或给出定时发布时间 | 已提交待审核，或已定时 |
| 作品管理确认已发布，或公开作品页与标题、作者一致 | 已发布，附平台提供的作品链接（如有） |
| 仅看到预览、转圈、断网或超时 | 结果待核对，保留当前稿件和已成功的其他平台记录 |

小红书、知乎以及通用编辑器的自动化回归使用真实浏览器与隔离的编辑器样例，覆盖输入、附件、预览及不同回执。Discourse 采用本地 MCP 服务验证。各平台的预置地址表示可以从该处开始配置，实际账号的公开投递需由使用者授权。
