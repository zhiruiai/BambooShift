# Bot 设置与智能组队

在聊天顶部的更多菜单选择“查看 Bot 详情”，或在成员面板点击 Bot，可进入统一资料设置面板；点击顶部名字本身打开会话详情。资料页编辑名字、六种原创头像的形状和颜色、角色与简介；工作方式页编辑长期指令。相关内容页连接已有的技能、会话文件和电脑面板。团队成员可查看资料，由空间拥有者保存配置。

角色、简介和长期指令会进入真实 Pi 任务上下文。保存影响随后开始的任务，已经在执行的任务保持启动时的配置；执行结束不会覆盖期间保存的新设置。多个窗口同时修改时会检查配置版本，冲突保留当前草稿，由用户决定是否载入最新版本。运行状态变化不导致配置版本变化。删除仍检查正在执行的任务、群聊最后成员和绑定的电脑画面。

## 从目标组成 Bot 工作组

左上角“+”提供创建 Bot、手动群聊和智能组队。智能组队属于 Bot 的工作协作，不是注册人类团队或邀请账号成员。

手动群聊先选择 2–6 位 Bot：收件人标签显示已选成员，第一位是负责人，可以按姓名或角色搜索、移除并重新选择。群名随名单自动建议；输入自定义名称后不再被选择变化覆盖，也可明确恢复建议名称。创建只保存群聊，不发送任务。桌面可用 Cmd/Ctrl+Shift+N 打开手动群聊，或用 Cmd/Ctrl+K 在“搜索与快捷操作”中选择新建群聊；拥有者还可直接进入智能组队或创建 Bot。已有设置弹窗打开时快捷键不会覆盖草稿，当前会话搜索仍只检索记录。

1. 写下目标，使用当前空间所选模型生成方案；没有配置模型时可直接打开现有模型设置，返回后保留目标和方案草稿，再明确点击生成。保存备用配置不会自动切换当前模型。
2. 模型优先复用现有 Bot，只建议补充缺少的职责，保持 2–6 位成员。生成仅规划，不执行目标，不创建 Bot。
3. 检查并编辑群名、协作方式、负责人、每位成员的分工，以及新 Bot 的资料与长期指令。可保存草稿，之后从最近方案恢复。
4. 确认后一次创建缺少的 Bot、各自私聊和协作群。复用的 Bot 保持原有配置、记忆和历史；群负责人不改变全空间的主 Bot。
5. 创建完成后，可打开群聊或明确点击“开始协作”。开始操作通过现有消息流程发送原目标；创建本身不会启动任务。

确认的目标和分工保存为群聊安排，进入负责人和实际子任务的上下文。已有的委派、电脑审批、应用审批继续生效。工作组移除成员后，新的委派不能再发给被移除者；普通私聊原有的空间内协作方式不变。

### 从团队模板开始

空间拥有者可在桌面、Web 和 Flutter 的「模板库 → 团队模板」或「智能组队」打开同一目录。Flutter 从模板库进入时，在当前空间核对未完成的请求，再展示模板；可以先预览分工，退出预览时不会保存方案。产品发布、财务月结和客户支持各有三位分工明确的 Bot，参考 Grok Bot 的团队案例，由 BambooShift 独立编写中英文方案。[团队案例](https://docs.x.ai/grok-bot/use-cases#build-a-team-of-bots-for-a-bigger-goal)

载入模板只保存一份待编辑方案，无需配置模型。空间拥有者可以先填写自己的目标，载入后调整群名、负责人和分工，也可以复用已有 Bot。确认创建与开始协作仍是两个独立操作。

## 管理已经创建的工作组

从会话详情中的“编辑本组安排”或成员页的“群聊设置”进入同一个管理窗口。可修改群名、选择负责人、增减成员；智能组队创建的工作组还可编辑目标、协作方式和每位成员的本组分工。已有群聊可保留或减少到一位成员，手动群聊不必补造一份团队计划。历史超过六人的群不截断名单，可改名、重排或减少原成员；在降至六人并保存之前，不能加入原名单以外的成员。旧单人方案仍可读取和编辑，确认新群前须补足两位。组内安排不改 Bot 的长期角色、指令、记忆或全空间主 Bot；保存本身不发送目标、不启动工作。

拥有当前团队空间访问权的成员沿用现有群聊编辑权限。保存一次提交完整安排并比较配置版本；收到新消息或已读状态变化不会制造设置冲突。其他页面已修改时保留当前草稿，先读取实际已保存的成员和分工，再明确选择载入或继续编辑。网络结果不确定时同样先核对，不自动重发保存；账号或空间切换后，旧响应不能写回新界面。

每个根任务开始时固定群成员候选和分工，稍后启动的子任务也使用这一份安排。保存后新根任务读取新配置，新发送且未定向的消息由新负责人处理；已经排队的消息保留原来确定的接收者。移除成员会立即阻止之后向它发起新委派，但不会自动停止已经开始的根任务或子任务。新添加成员也不会突然加入已经开始的这一轮工作。

Bot 资料面板现在有直接打开已有会话的按钮，未保存的设置先经放弃确认。个人空间明确显示私人会话，团队空间标注团队可见；不创建替代会话、不改变隐藏名单。智能组队配置模型时保留原向导子树，只有当前显示的弹窗接收键盘和焦点操作；返回原方案不触发生成、创建或开始协作。

## 在聊天中提出团队

也可以直接对 Bot 说：“为这个项目组建团队，优先复用已有同事，先给我看看分工。”当前聊天模型可通过 `propose_team` 保存一份方案，消息中显示目标、成员、负责人和待确认状态。点击卡片进入上面的同一个方案编辑器，支持修改、保存草稿、取消和确认；不是另一套创建逻辑。

工具仅生成可审阅的草稿，不另开独立规划模型，不创建 Bot 或群聊，不开始目标。普通团队成员也可以让 Bot 提案，由空间拥有者查看完整方案并确认。每个人类消息发起的主任务最多保存一份提案；子任务、例行任务和没有可信用户输入的直接运行不开放该工具。工具完成后，当前 Bot 可继续正常回复。

卡片来源由服务端绑定实际聊天、Bot、用户消息和运行身份，模型不能指定身份或批准自己。编辑、取消和创建都更新同一条卡片，保留已有回应和引用；源聊天或提出方案的 Bot 被移除会取消尚未确认的提案，已经创建的结果保留。停止任务不会删除之前已保存的草稿，但停止或撤权之后不能再发布迟到的提案。

打开已创建团队前会重新核对真实群聊及成员，已删除的群聊不会从旧回执中重新显示为存在。开始协作继续使用原有消息去重，不能因重复点击再次执行同一个目标；目标消息单独发送，保留该群已经写好的文字、附件和引用草稿。

发送从本地回执计算到请求完成都绑定原账号与空间，离开页面或切换后不继续发送、不把迟到结果写入新页面。服务端在写入消息前再次核对请求中预期的账号；当前账号的普通团队成员仍可正常发消息。

## 恢复与实现

规划状态保存在空间 SQLite 的 `bot_team_plans` 表。每个空间同一时间只生成一个方案，模型调用限制为一分钟、最多 4096 输出 token，禁用自动重试，只声明用于返回方案的 `propose_team`，没有工作工具执行器。模型输出必须经过完整校验；缺少有效工具参数、截断、取消或失败均不能用静态模板假冒成功。

生成和确认分别使用唯一请求标识；重复确认返回同一个已保存结果，不重复创建 Bot。确认在一个 SQLite 事务中同时写入 Bot、私聊、群聊和回执。复用 Bot 的配置变化会拒绝旧方案，避免把已改变职责的 Bot 静默编入团队。草稿保存检查版本并产生新版本，迟到的旧确认无法覆盖新方案；读取状态本身不生成、创建或启动工作。

退出账号、空间权限变化、取消和超时会中止生成，迟到结果不能发布；重启后未完成的生成标记为中断，目标保留。所有方案接口仅空间拥有者可用，平台运营会话不能代替空间账号访问。

API 位于 `/api/workspaces/:workspaceId/bot-team-plans`：`POST /` 生成，`GET /` 或 `GET /:id` 恢复；`POST /:id/revise` 保存草稿，`POST /:id/commit` 确认创建，`POST /:id/cancel` 取消。移动端从相邻的 `GET /bot-team-templates` 读取语言匹配的模板目录。创建请求提供模板标识和语言时，服务端从目录载入并校验待编辑方案。重试返回原方案，避免重复创建。手动新建 Bot 与群聊使用独立 `/creation-requests` 持久回执；修改 Bot 仍用 `/agents/:id`，新前端保存时携带 `expectedRevision`。旧 Bot 记录的配置版本可稳定派生，读取旧资料不会写入随机版本。

已创建工作组由独立的 `GroupSettings` 管理，`GET/PATCH /api/workspaces/:workspaceId/conversations/:id/settings` 只处理群聊配置。版本根据群名、成员顺序和分工计算，在 SQLite 事务中检查并更新现有会话行，不另建方案或保存回执表。来源共享 Bot 的主私人会话不能通过此入口改成工作组。旧成员编辑和删除 Bot 的路径同步修复负责人及分工；运行时的群安排快照与当前成员资格分别检查。

## 实际执行与验收边界

Rust 通过智能体工作进程协议运行 Bot，模型身份与执行引擎分开。现有发布包和源码入口保留 `pi-worker` 路径以兼容部署；该路径不向模型提供插件选择权，也不允许从聊天或工作区导入任意代码。当前只提供受审查的内置 Pi 实现，不增加没有实际第二实现的引擎选择设置。

负责人通过 `delegate` 发起真实子任务，工具等待子任务结束后返回结果、状态和结果消息 ID。子任务失败时，工具同时返回 `isError: true`，保留实际错误内容；负责人仍可以正常回复阻塞原因或安排后续工作。消息的“已完成”表示这一轮回复结束，不表示软件已经通过测试或交付验收。

同一空间的成员可通过现有工作区文件工具交接成果，文件读取和写入提供 SHA256，带预期摘要的修改会拒绝覆盖已经变化的文件；正式文件交付还会核对版本并生成文件卡片。委派的文本摘要最多返回 16,000 字符，大型产物应保存在工作区，并由接手者重新读取。子任务不会自动获得额外文件、电脑或应用权限。停止、撤权和新要求的代际检查沿用现有执行机制，未确认的电脑操作仍需恢复核对，不会自动重放。

普通根任务与全部委派子任务共用最多 30 分钟的执行预算，等待工具或审批也计入，委派不会重新获得整段时长。到期先停止现有操作权限并等待清理，再结束任务；不会把一个仍在执行的子任务当成已完成，也不会自动重放结果未知的操作。更长的软件工作应保存阶段产物与进度，再由用户继续发起下一轮。

团队模板和分工是协调指令。目前没有持久化的任务依赖图、自动阶段验收或跨重启恢复调度；负责人需要按依赖顺序等待委派结果、读取真实产物并核对检查记录。不得仅根据成员自述或成功结束的模型回合宣布整个项目完成。软件团队的阶段分工和交付要求见[软件产品团队](software-product-team.md)。

## 验证范围与后续差异

聊天提案也已通过真实 GLM 验证：一次提案工具调用和随后的正常回复，共两次模型请求；确认前只有原来的三位 Bot 和一段合成对话，随后在临时数据库中明确确认，产生新 Bot、私聊和协作群，原卡更新为已创建。没有修改正式 Bot 或执行外部工作，见[聊天组队实测](evidence/glm-chat-team-proposal-20261105.json)。

## 2026-11-05：资料与组队草稿细节

只读 Bot 资料打开期间，来源名称和角色随最新配置刷新，与头像保持一致。智能方案中把新 Bot 临时换成已有 Bot，再切回来，会保留先前的新 Bot 名称、角色、简介、长期指令与已确认头像，同时保留期间调整的分工；这份备选草稿只在当前编辑器保留，明确重载其他方案时清理。此切换不调用模型、不自动创建 Bot。

例行任务可以从面板回到负责 Bot 的原会话，用聊天创建或修改，保留已有消息草稿；参见[聊天任务设置](routine-chat.md)。本轮真实 GLM 已验证创建指定每周计划、再改时刻并暂停，见[合成验收记录](evidence/glm-routine-chat-20261105.json)。登录后的设置与组队仍需实际 GUI 验收；浏览器已恢复，临时测试账户创建正等待用户审批。

智能方案现已补上[显式资料核对与恢复](team-catalog-review.md)：可以接纳生成后新增或已修改的 Bot，保留原目标、草稿和分工；只读预览、保存资料和最终创建分开。手动新建 Bot/群聊也支持[原请求恢复](manual-creation.md)：创建完成后再打开会话，断线先核对，不重复创建；明确结束未接纳请求会阻止迟到提交。不能将这些修复视作完整复刻验收。
