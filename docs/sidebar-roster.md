# Bot 名单整理

名单整理参考 [Grok Bot 的组织说明](https://docs.x.ai/grok-bot/bots)：置顶常用 Bot，按项目或客户分区，把暂时不用的 Bot 隐藏，并能从隐藏列表恢复。隐藏保留历史和工作能力，不暂停例行任务。

## 个人偏好与团队资源

每个成员在每个空间分别保存自己的置顶、隐藏和分区。团队拥有者和普通成员都可以整理自己的列表；其他成员的列表、Bot 配置和群聊成员不受影响。平台运营身份不代替产品账号整理名单。偏好存于后台 SQLite，同一账号在不同设备上同步。

单人会话按 Bot 归类，同一 Bot 的多条单人会话共用偏好；群聊独立归类，隐藏某个 Bot 不隐藏它参加的群聊。主 Bot 也遵循名单整理，隐藏不解除主 Bot 身份或关闭每日跟进。

分区名称、折叠状态和成员归属一起保存。置顶后暂时排在置顶区域，原分区归属仍保留，取消置顶后回到原分区。删除分区只把其中的条目移回默认列表，保留 Bot、群聊、隐藏与置顶状态。

隐藏不会清空已打开的会话或输入草稿，也不会因 Bot 的新消息、状态更新或服务器重启自动恢复。用户可以从隐藏列表恢复，或在全局消息搜索中找到历史并继续聊天。搜索结果本身不修改隐藏状态。

## 存储与同步

独立的名单偏好表按服务端认证得到的账号标识隔离。未启用账户体系的旧本机模式使用固定的本机身份；注入了账户访问策略却缺少可信账号时，不降级为本机身份。新接口不接受由请求正文指定的账号。

`GET /sidebar-roster` 读取自己的偏好；`PUT /sidebar-roster` 使用期望版本和一个明确操作，原子完成置顶、隐藏、移动、创建、重命名、折叠或删除分区。缺失目标、无效分区或旧版本不会部分保存。首次读取不迁移或写入数据；没有个人偏好记录时兼容旧的置顶值，第一次保存后使用独立偏好。

Bootstrap 仅包含当前成员的名单设置，实时事件只通知需要重新同步，不发送另一个成员的分区名称或隐藏状态。旧的共享 `conversation.pinned` 写入入口明确拒绝，避免形成绕过个人隔离和版本保护的第二条写入路径。

页面的同步请求固定绑定打开时的账号与空间，并携带期望账号。若另一个登录替换了浏览器会话，服务端拒绝旧页面的身份不匹配请求；前端也不接收切换后的迟到响应。原有不携带该字段的客户端仍只能读取实际登录账号的数据，不能用字段指定要读取的其他账号。

## 验收

2026-11-05，[真实 HTTP 验收](evidence/sidebar-roster-http-20261105.json)使用临时个人与团队账户，确认成员独立设置、第二次登录同步、服务器重启持久、版本冲突、删除分区保留置顶与隐藏，以及切换登录后拒绝旧页面的身份不匹配请求。隐藏个人主 Bot 后，其选择与已启用的每日跟进设置保持不变。原有 Bot、会话、消息、记忆、技能、例行任务、文件及设置的数据库指纹未改变；临时数据已清理。

[完整验证记录](evidence/sidebar-roster-verification.json)：服务端 509 项与前端/桌面 176 项通过，2 项仅适用于 Linux 的检查跳过。类型、20 个变更源码的格式和生产构建通过。[本机服务检查](evidence/sidebar-roster-service.json)通过 18 个页面与受保护接口入口，原有正式数据基线未改变。本轮没有调用付费模型或操作远程电脑。

产品浏览器仍返回 `Local browser use is disabled in Work settings`，新增菜单、分区布局和手机触控尚未经过实际页面验收。组件事件、源码 SSR 与接口检查不作为真实产品 GUI 验收。
