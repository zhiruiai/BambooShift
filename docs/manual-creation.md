# 手动创建与结果恢复

左上角“+ → 创建 Bot / 新建群聊”共用持久创建回执。创建完成后先显示结果，再由用户打开会话或继续新建；打开前重新核对原会话，列表暂时刷新失败不影响已经创建成功的事实。智能组队仍使用自己的方案与确认流程。

每次明确创建都有独立请求标识。网络断开、响应丢失或重新打开弹窗时，先查询原结果；刷新后仍能核对。当前页还保留原提交内容时，可明确重试同一请求，不产生第二份 Bot 或群聊。浏览器只保存请求标识、类型与摘要，不保存长期指令、群成员正文或凭据；正文仅在当前页面内存中保留。存储不可用时不提交。

没有查到结果不等于尚未创建。用户可以继续核对，或明确结束这次核对：服务端若已经接纳，返回原结果；若尚未接纳，永久关闭此请求标识，之后迟到的同一提交也不能创建。关闭确认丢失时仍保留原请求，重新查询。Bot、原私人会话或群聊已被删除时显示不可用，不创建替代品。合法修改后的工作组返回当前名称与成员，原创建绑定保持不变。

团队成员可以创建群聊，空间拥有者可以创建 Bot。回执属于原账户与原空间；原拥有者降为成员后可以核对自己已经创建的结果，但不能再创建 Bot。账户被移出空间或原登录失效后不能继续操作；另一登录账号不能通过请求标识取得原回执。

`CreationRequests` 负责三条接口，位于 `/api/workspaces/:workspaceId/creation-requests`：

- `POST /`：提交 `{ kind: 'bot', requestId, profile }` 或 `{ kind: 'group', requestId, title, agentIds }`。
- `GET /:requestId`：只读核对当前结果；未找到返回 404，已关闭但未创建返回 410。
- `POST /:requestId/cancel`：空请求体结束核对，返回已接纳结果或已关闭确认。

Bot、私人会话、头像发布与回执在同一 SQLite 事务中保存；群聊与回执也一并保存。事务内复核原身份、当前拥有者权限与所选 Bot，拒绝不可用的共享来源。回执表只保存摘要和原实体标识，不另存完整 Bot 资料；同一标识改交另一份内容返回冲突。新界面使用这些接口，旧 `/agents` 和 `/conversations` 创建接口保留兼容，不提供这套恢复保证。

创建不调用模型、不发送目标、不启动任务。独立临时数据下的领域、HTTP 和 React 事件检查覆盖重试、丢响应、重启、删除、撤权、封存与草稿保留；最终数量见[验收记录](verification.md)。这些检查不能替代真实页面的视觉、焦点和触控验收。浏览器已可用；登录后的实际操作仍待临时测试账户的明确授权。
